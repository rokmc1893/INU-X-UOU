# 정책 풀·실시간 수집 설계 (A+B+업데이트 경로)

승인: 제품책임자, 2026-08-13 저녁. 마감: 08-14 08:00 (코어는 금일 중 완료).

## 목적

공무원의 실제 진입 흐름을 실물로: **산업을 선택하면 관련 정책이 풀에서 딸려오고(A)**,
**URL을 붙여넣으면 그 자리에서 수집·추출되어 분석에 추가되며(B)**,
풀은 **스크립트 재실행으로 갱신 가능(백그라운드 업데이트 경로)**하다.

## 구조

```
06_앱/data/pool/
├─ B1_policy_portfolio.csv     # F4 조사자 B 원장 사본 (52건, stable_policy_id + version)
└─ cards/IC-*.json             # 산업별 카드 (engine/pool.py 배치 산출)

engine/pool.py    # B1 행 → 의사원문 텍스트 → extract_card 재사용 → 카드. CLI 재실행 = 풀 갱신
engine/fetch.py   # URL → HTML → 본문 텍스트 + 메타헤더 (표준 html.parser)

앱 사이드바:
  분석 범위 [청년일자리(기본) / 청년일자리+바이오]   ← A
  "URL로 정책 가져오기" 입력 + 버튼 (실패 폴백)      ← B
```

## 정직성 규칙 (B_README 준수)

- 카드에 `evidence_status`(SECONDARY_PRESS_ONLY / CONFLICTING_FIGURES / …) 뱃지 그대로 노출
- B1의 `UNKNOWN` 값은 null 기권으로 변환, `CONFLICTING:` 수치는 화면에 올리지 않음 (null + 충돌 표시)
- 중첩은 "후보"로만, K-NIBRT 수행주체는 연세대 사업단 (E016)
- URL 수집 카드는 `retrieved_at` 표시, 세션 한정(파일 저장은 raw만)

## 예상 판정 변화 (수용)

바이오 풀 결합 시 K-NIBRT 교육과정이 바이오 수요를 특정 커버 → "공백"이
"**부처·포트폴리오 경계의 인계 공백**"으로 바뀐다 — 다산업 결합의 가치를 화면으로 증명.

## 범위 밖

검색엔진 자동 서칭, 스케줄러 등록(작업 스케줄러/cron은 운영 로드맵 — 갱신 스크립트까지만),
바이오 외 4개 산업 카드 변환(구조는 동일하므로 시간 남으면).
