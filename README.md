## 30초 요약

**무엇을 만들었나.** 인천시 청년 일자리 정책 사이의 **지원 공백 · 인계 공백 · 조정 필요 중복 · 의도적 병행 · 보완 관계**를 규칙으로 판정해, 공무원이 신규사업 검토 3단계에서 쓰는 **「유사·중복 사업 자체 검토서」 초안**을 만들어 주는 Streamlit 앱.

**왜 이걸 만들었나.** 2025년 인천은 순유입률 1.1%로 전국 1위였다. 청년이 떠나는 게 아니라 **32.8%가 직장을 인천 밖에 두고** 있었고, 이유 1위는 "원하는 직무의 일자리가 없어서"였다. 임금과 직무는 소프트웨어가 못 바꾼다. 대신 **정책 결정의 품질**은 바꿀 수 있다.

**설계의 핵심.** LLM은 원문→카드 **추출에만**, 판정은 **규칙**, 결정은 **사람**. `engine/detect.py`에 `import openai`가 없다는 것이 물증이고, 그걸 검사하는 테스트가 있다.

```bash
cd 06_앱
pip install -r requirements.txt
cp .env.example .env      # OPENAI_API_KEY 입력 (없어도 앱은 뜬다)
python -m streamlit run app.py     # → http://localhost:8501
```

앱·인터넷이 전부 죽어도 `06_앱/data/demo_fallback.html`을 브라우저로 열면 핵심 화면이 그대로 나온다.

## 4화면이 하는 일

| 화면 | 답하는 질문 |
|---|---|
| **1 검토 개요** | 지금 이 정책들에 무슨 문제가 있나 · 언제까지 처리해야 예산에 반영되나(A2 달력) |
| **2 정책 연계 지도** | 청년이 어디서 끊기나 (결재란 사슬 ✂) · 누구와 협의해야 하나(A3 검토자) |
| **3 유사·중복 검토표** | 겹치는 게 낭비인가 아닌가 (중복 / 의도적 병행 / 보완) · 판정 근거 Cypher |
| **4 조치 제안서** | 그래서 뭘 하면 되나 · **검토서 초안 다운로드** · 추출 정확도 실측 |

**사이드바 ①번**에 신규사업(안)을 붙여넣으면 **내 사업 ↔ 기존 사업**을 대조한다. 3단계 업무의 실제 입력이다.

## 정직성 원칙 — 이 프로젝트가 지킨 것

- **원장에 없는 수치는 발표자료에 올리지 않는다.** 모든 수치에 증거 ID(E0NN)가 붙는다.
- **실데이터와 가상 데이터를 화면에 구분 표기한다.** 수요신호 5건 중 2건이 가상임을 사이드바에 명시한다.
- **불리한 수치를 지우지 않는다.** 인용 실재율이 91%→81%로 내려간 것을 그대로 공개한다.
- **판정은 전부 "후보"다.** 타 부서 사업에 "중복 확정"을 찍지 않는다.
- **못 하는 것을 먼저 말한다.** 실제 공무원 검증 없음 · 홀드아웃 셋 없음 · 배포 불가 · 검토서 서식 미확인.
