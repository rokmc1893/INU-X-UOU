## 슬라이드별 메시지

### 2. 문제 발단

**한 문장:** 청년 유출은 앱 하나로 해결되는 문제가 아니다.

- 배정 주제를 그대로 읽으면 "청년-기업 매칭 플랫폼"으로 간다. 우리는 거기서 멈추지 않았다.
- `[사실]` 확인해보니 인천 청년은 **주소 기준으로는 순유입**이다. → E005
- 실제로 벌어지는 일은 "떠난다"가 아니라 **인천에 살면서 관외로 출근한다**. → E006
- 청년의 선택을 좌우하는 건 임금·기업규모·직무다양성·경력전망이다. **소프트웨어가 이걸 직접 바꿀 수는 없다.**

> 시각자산: 통념(순유출 화살표) vs 확인된 사실(순유입 + 관외통근) 대비 도식

### 3. 재정의

**한 문장:** 바꿀 수 없는 것 대신, 바꿀 수 있는 것을 찾았다 — **정책 결정의 품질**.

- 추진 사업이 산업 수요에 맞게 결정되고, 부서별로 흩어진 정책이 공백·중복 없이 연결될 때 → 지역산업 발전 → 양질의 일자리 → 청년 정착이 **간접적으로** 따라온다.
- 그래서 I3의 두 축 중 **'산업·정책 연계 부족'을 직접 타겟**으로 삼았다.
- `[사실]` 그리고 실제로 인천에서 벌어지는 일도 대부분 **기존사업 조정**이다. 제2차 청년정책 기본계획 69개 사업 중 계속·확대가 **85.5%**, 교육·훈련 분야는 **92.3%**다. → E008·E010
  - **한계를 반드시 붙일 것:** 이건 인천 청년정책 포트폴리오 한정 수치다. "지자체 세출 대부분이 계속사업"이라는 전국 명제로 말하지 않는다.
- **핵심 인사이트 (문구 확정 — 이대로 말할 것):**
  > 연계 부족의 해법은 유사 서비스 사업을 하나 더 만드는 것이 아닐 가능성이 높습니다.
  > 그러나 **기존 사업을 실제로 이어 주는 권한·정보·인계장치는 새로 만들어야 할 수 있습니다.**
- 즉 우리는 `기존사업 수정` vs `신규정책 신설`을 이분법으로 고르지 않는다. **기존 수단의 재설계 + 필요한 신규 연결장치의 조합**을 제안한다.

> **주의 — 이렇게 말하면 틀린다:** "새 정책을 만드는 건 중첩을 하나 더 추가하는 일이다"는 과잉 단정이다. *비슷한 서비스 사업*을 추가할 때만 해당한다. 공동 의뢰·데이터 연계·인계 프로토콜 같은 조정장치는 오히려 직접 해법이다. (D-007 참조)

> 시각자산: 인과사슬 4단계 도식 (D-002 참조). 뒤 2단계에 "플랫폼에 귀속하지 않음" 명시.

### 4. 기존 방식과 남은 공백

→ `04_선행서비스_비교.md`의 결론 표와 문장을 그대로 사용.

**한 문장:** 기존 도구는 전부 정책을 *찾아주는* 도구다. 정책을 *만드는 사람*을 위한 도구는 확인되지 않았다.

### 5. 해결 원리

**한 문장:** 흩어진 사업들을 같은 구조로 정규화하면, 사람 눈에 안 보이던 관계가 보인다.

- 각 사업을 `문제 → 대상 → 수단 → 시기 → 예산 → KPI`의 공통 카드로 정규화
- 정규화된 카드들 사이에서 **공백 / 역할중첩 / 인계단절 / 시차**를 규칙으로 탐지
- **AI가 하는 일과 하지 않는 일을 명확히 구분** — LLM은 원문에서 필드를 추출하고 후보를 제안, **판정은 규칙, 결정은 사람**
- LLM 금지 목록을 화면에 노출: 출처 없는 사실 보완 / 정합성 점수 직접 생성 / 사업폐지·예산삭감 자동결정

> 이 슬라이드가 AI2(기술 이해도)와 AI6(책임 있는 AI)를 동시에 먹는 지점이다.

### 6. 라이브 데모 (150초)

확정된 4화면 흐름 (D-007):

```
[1] 성과 질문 + 기준사업
    "인천 바이오 생산·품질 인재양성이 실제 채용으로 이어지지 않는 단절은 어디인가?"
    기준사업: 인천 청년도약기지 생산·품질관리 과정
    → 사업 하나를 고립시켜 평가하지 않는다는 걸 첫 화면에서 선언
   ↓
[2] 정책사슬 X-ray
    문제→대상→수단→산출→중간성과→최종성과
    표시는 '설계상 단절 후보' / '집행데이터 확인 필요' / '담당자·수혜자 검증 필요'
    → 인과를 확정하지 않는다
   ↓
[3] 수요–정책 커버리지 행렬
    정책 공백 후보 / 인계 단절 / 해로운 역할중첩 후보 /
    접근성·전문성·실험을 위한 '의도적 중첩'   ← 네 번째를 반드시 보여줄 것
   ↓
[4] 판정 카드 — 단일 택일 아님
    주조치 / 보조조치 / 새로 필요한 것 / 새로 만들 필요가 낮은 것 /
    추가 검토 / 근거 수준
```

**발표에서 이 두 장면이 점수를 만든다:**
- 화면 3에서 **"이건 중첩이지만 의도된 중첩입니다"**라고 말하는 순간 — 유사성을 자동으로 낭비 판정하지 않는다는 설계 성숙도를 보여준다 (CRE3·AI2)
- 화면 4에서 **"새로 만들 필요가 낮은 것"** 칸을 짚는 순간 — AI가 무조건 신규 제안을 뱉는 도구가 아니라는 걸 증명한다 (AI1·AI6)

**필수:** 화면 어딘가에 `실데이터` / `가상데이터` 라벨이 항상 보여야 한다. (루브릭 DATA_INTEGRITY)
**필수:** 시연 실패 대비 **녹화 백업**을 준비한다. 발표 중 API 장애는 실제로 일어난다.

### 7. 검증

**한 문장:** 저희는 취업률을 올렸다고 말하지 않습니다.

| 검증한 것 | 검증하지 않은 것 |
|---|---|
| 정책 필드 추출 정확도 (정답셋 대비) | 실제 취업·근속 증가 |
| 핵심 판단의 원문 인용률 | 기업 매출·투자·고용 증가 |
| 근거 부족 시 `미확인`으로 기권하는 비율 | 청년 순유출 감소 |
| 유사하지만 중복 아닌 사업의 오탐률 | 기관 도입 의향 |

> **이 표가 AI5와 REG6를 동시에 올린다.** "못 한 것"을 먼저 말하는 팀은 드물고, 루브릭은 정확히 그걸 4~5점 조건으로 요구한다.

### 8. 한계와 다음 단계

- 공개데이터만으로는 정책의 인과효과를 증명할 수 없다 — 기관 협약 후 익명 집계 코호트로 확장
- 개인정보를 전혀 사용하지 않았다 (설계상 NO-GO로 못박음)
- 첫 검증은 인천 바이오지만, 산업 교체 필드만 바꾸면 다른 산업·지역으로 확장 가능
