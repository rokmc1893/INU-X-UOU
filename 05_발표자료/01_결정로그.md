## D-001 · 주제를 '청년 유출'이 아니라 '산업·정책 연계 부족'으로 타겟팅

**상태:** 확정
**결정일:** 2026-08-12 (2일차 이전 논의에서 확정, 08-13 재확인)

**결정 내용**
배정 주제 I3의 두 축(`청년 인재 유출` / `지역 산업·정책 연계 부족`) 중 **후자를 직접 타겟**으로 삼고, 청년 유출은 장기 결과 지표로 재배치한다.

**근거**
1. `[사실]` 공식 통계 확인 결과, 최근 인천 청년은 **주민등록 주소 기준으로는 순유입** 경향이다. 안내자료의 "청년 인재 유출"이라는 표현을 주소이동으로 해석하면 근거와 맞지 않는다.
   - 검증 필요: 조사자 B가 KOSIS 국내인구이동통계에서 인천 20~34세 순이동 수치를 확정하고 `03_증거원장.csv`에 등록할 것.
2. `[사실]` 인천 거주 청년 상당수가 **관외(주로 서울·경기)로 통근**하며, 역외취업 사유로 직무·임금 차이가 조사된 자료가 있다.
3. `[추론]` 따라서 실제 문제는 "사람이 떠난다"가 아니라 **"지역 안에 양질의 경력경로가 형성되지 않는다"**이며, 이는 산업 수요와 정책이 어긋난 결과다.
4. `[추론]` 청년의 거주·취업 선택은 임금·기업규모·직무다양성·고용안정·통근·조직문화가 좌우한다. **소프트웨어가 이를 직접 바꿀 수는 없다.** 반면 **정책 결정의 품질은 소프트웨어로 개선 가능하다.**

**발표에서 쓸 문장**
> 청년 유출은 앱 하나로 해결되는 문제가 아닙니다. 그래서 우리는 개입 가능한 지점으로 한 단계 올라갔습니다 — 추진 사업이 산업 수요에 맞게 결정되고, 부서별로 흩어진 정책이 공백·중복 없이 연결될 때, 지역산업 발전과 청년 정착은 **간접적으로** 따라옵니다.

**주의**
이 논리는 "우리는 주제를 안 풀었다"로 들릴 위험이 있다. 반드시 **재타겟팅 = 문제 재정의**로 프레이밍하고, 인과사슬 도식(D-002 참조)을 함께 보여준다. 루브릭 CRE2(문제 재정의·핵심 인사이트)의 최대 득점 포인트이자, REG1(현안 정의 구체성)의 최대 리스크 지점이다.

## D-002 · 성과 귀속을 4단계로 분리하고, 뒤 2단계는 플랫폼에 귀속하지 않는다

**상태:** 확정
**결정일:** 2026-08-12

**결정 내용**
```
정책핏의 직접효과      근거 완전성·검토속도·누락탐지·결정 추적성      [플랫폼 귀속: 높음]
        ↓
행정 중간효과          사업 보완·연결·통합·신설, 예산조정, KPI 개선   [중간]
        ↓
정책의 사업성과        기업 충원·매출·투자, 취업·임금·근속            [낮음]
        ↓
지역 장기성과          산업생태계·지역격차·인재정착                   [매우 낮음]
```

**근거**
1. `[사실]` 루브릭 §7은 "확인 방법 없는 성능 수치 또는 사용자 반응을 사실처럼 제시"할 경우 `UNVERIFIED_CLAIM` 플래그와 함께 AI5 또는 REG6에 **최대 1점** 상한을 건다.
2. `[추론]` 3일 해커톤에서 취업률 상승이나 청년 순유출 감소를 증명하는 것은 불가능하다. 증명할 수 없는 것을 주장하면 감점이지만, **한계를 명시적으로 선언하면 오히려 REG6·AI5의 가점 요인**이 된다.

**발표에서 쓸 문장**
> 저희는 취업률을 올렸다고 말하지 않습니다. 저희가 검증한 것은 **정책 설계의 미스매치를 원문 근거로 정확히 찾아냈는가**입니다.

## D-003 · 데모 진입경로를 '입구 A(기존사업 개선)' 단일로 고정

**상태: 개정됨 → D-007로 대체.** 방향(기존사업 기준점)은 유지되나 첫 화면 형태와 근거 논리 3개가 교정됨. 아래는 개정 전 기록으로 보존한다.
**결정일:** 2026-08-13

**결정 내용**
세 진입경로(A 기존사업 / B 현안 / C 신규안) 중 **입구 A만 구현**한다. 단, 산출물의 마지막에 "그래도 신설이 필요한가?" 판정 카드를 넣어 서사는 신규안 검토까지 도달시킨다. 신규안 입력 UI는 만들지 않는다.

**근거**
1. `[추론]` **연계 부족은 정의상 기존 사업들 '사이'의 문제다.** 연계·중복·인계단절은 둘 이상의 기존 사업 사이에서만 성립하는 관계 개념이다. 정책이 없어서 생기는 문제가 아니라, 이미 있는 정책들이 서로를 모른 채 각자 돌아가서 생긴다.
2. `[추론]` 따라서 **신규 정책을 하나 더 만드는 것은 연계 부족의 해법이 아니라 역할중첩을 하나 더 추가하는 행위일 수 있다.** 이것이 발표에서 쓸 비자명한 인사이트다.
3. `[추론 — 검증 필요]` 지자체 예산 구조상 세출 대부분은 계속사업이고, 매년 실제로 벌어지는 결정은 "연장·확대·축소·통폐합"이다. 신규사업은 시장 공약·중앙부처 공모 대응·신규 계획 수립 같은 계기가 있을 때 발생하며 재정투자심사 등 절차가 무겁다. **즉 빈도상으로도 기존사업 조정이 압도적이다.**
   - **조사자 B 확인 과제:** 지방재정365 또는 인천시 예산서에서 바이오·청년일자리 분야 세부사업의 **계속사업 vs 신규사업 건수·금액 비중** 수치 1개 확보. REG2용 A/B급 증거가 된다.
4. `[추론]` 신규사업 검토 시점에도 절차상 "유사·중복사업 검토"가 요구된다. 그것이 형식적으로만 이뤄진다면 **바로 그 지점이 서비스의 진입점**이다. 결국 신규안 검토조차 기존사업 지도가 있어야 가능하다.
5. `[사실]` 구현 시간이 오늘 약 5시간뿐이다(D-005). 진입경로 2개를 만들 여유가 없다.

**대표 결정질문 (변경 없음)**
> 현재 사업들을 그대로 운영할 것인가, 역할을 재설계·연결할 것인가, 별도의 취업전환 정책이 필요한가?

**폐기한 대안**
- 입구 B(현안 입력): 라이브 입력이라 AI4에 유리하지만 생성 범위가 넓어 환각·지연 리스크가 크다.
- 입구 C(신규안 검토): 입력물인 제안서를 우리가 지어내야 해서 자작극으로 보일 위험.
- A→C 전체 흐름 구현: 서사는 최적이나 구현량 초과.

## D-007 · 데모 첫 화면 = '성과 질문 + 사전 선택된 기준사업(anchor)' (D-003 개정)

**상태:** 확정
**결정일:** 2026-08-13
**출처:** `../04_핸드오프/03_closed/H001_CODEX_TO_CLAUDE_DEMO_ENTRY_VERIFICATION.md` — HANDOFF §19 미결정 항목 #8 확정

**결정 내용**
첫 화면은 **성과 질문 + 사전 선택된 기준사업**으로 고정한다. 세 진입경로를 고르는 분기 UI도, 기존사업 한 건만 고르는 화면도 만들지 않는다. 기준사업을 출발점으로 **주변 사업군까지 함께** 진단한다.

```
화면 제목: 인천 바이오 생산·품질 인재양성이 실제 채용으로 이어지지 않는 단절은 어디인가?
성과 질문: 교육 → 채용 전환의 단절은 어디인가?
기준사업:  인천 청년도약기지 생산·품질관리 과정
분석 범위: 인천 청년 / 생산·품질 직무 / 교육→채용 전환
안내문:    기준사업 한 건만 평가하지 않고, 같은 대상·직무·시기에 작동하는 주변 정책과 함께 비교합니다.
주 CTA:    주변 정책과 함께 진단하기
```

**4화면 흐름**
1. 성과 질문 + 기준사업 — 사업 하나를 고립시켜 평가하지 않는다
2. 정책사슬 X-ray — `문제→대상→수단→산출→중간성과→최종성과`. 결과는 `설계상 단절 후보` / `집행데이터 확인 필요` / `담당자·수혜자 검증 필요`로만 표시하고 인과를 확정하지 않는다
3. 수요–정책 커버리지 행렬 — `정책 공백 후보` / `인계 단절` / `해로운 역할중첩 후보` / **`접근성·전문성·실험을 위한 의도적 중첩`** 네 가지를 구분한다. 유사성을 자동으로 낭비로 처리하지 않는다
4. 판정 카드 — 단일 택일이 아니라 **주조치 + 보조조치 + 새로 필요한 것 + 새로 만들 필요가 낮은 것 + 추가 검토 + 근거 수준**의 조합

**빈도 근거 (D-003 근거3의 검증 결과 — 추론이 인천 실데이터로 확인됨)**
- `[사실]` 인천 제2차 청년정책 기본계획(2026~2030): 전체 69개 사업 중 계속 51 · 확대 8 · 신규 10 → **계속·확대 기반 85.5%** → E008
- `[사실]` 일자리 분야 21개 중 계속·확대 17개 → **81.0%** → E009
- `[사실]` 교육·훈련 분야 13개 중 계속 12개 → **92.3%** → E010
- `[사실]` 2027년 국비 확보 중점관리 67건 중 신규 17 · 계속 50, 요청액 기준 신규 약 2.8% → E011

**적용 한계 (발표에서 반드시 붙일 것)**
이 수치는 **인천 청년정책 포트폴리오와 국비 중점관리 사업군**에 한정된다. `지자체 세출 대부분이 계속사업`이라는 전국 일반명제로 확대하지 않는다. 인천시 전체 본예산이나 실제 집행 포트폴리오를 대표하지도 않는다.

**D-003에서 교정된 주장 3개**
| 개정 전 (과잉 단정) | 개정 후 |
|---|---|
| 연계 부족은 **정의상** 기존 사업들 사이의 문제다 | 중첩과 인계단절은 여러 기존 사업의 관계에서 드러나는 경우가 많다. 다만 연계 부족은 **필요한 권한·데이터·의뢰절차·성과추적 장치 자체가 없어서**도 발생하므로, 진단 결과 새로운 연결장치가 필요할 수 있다 |
| 신규 정책을 만드는 건 역할중첩을 하나 더 추가하는 행위다 | **비슷한 서비스 사업**을 추가하면 중첩이 늘 수 있다. 그러나 공동 의뢰·데이터 연계·인계 프로토콜 같은 **새로운 조정장치는 오히려 연계 부족의 직접 해법**일 수 있다 |

2. `[사실]` COVERS를 특정성 없이 구현한 첫 판정에서 공백이 0건으로 나왔다 — 정장대여(전직무)가 바이오생산 수요를 "커버"한 것으로 처리됐기 때문. 특정성 구분 도입 후 공백 = 바이오생산·바이오품질 2건으로 기준사업 서사와 일치.

## D-014 · 추출 프롬프트 v2~v4 반복 — 정답셋 기반 개선 실측

**상태:** 확정
**결정일:** 2026-08-13 19:10 무렵

**결정 내용 / 사실 기록**

- v3→v4: 구직지원 4종이 전부 "조정 필요 중복"으로 묶인 원인은 target 구조체가 소득기준·재학생 허용 차원을 못 담았기 때문 → `student_status`·`income_criteria` 추가 (원문 명시 시에만 추출) → 오판 회피 0→100%.

- v5→v6: 모델이 occupation을 지원 자격으로 코딩(P009 SW·AI 교육이 '시민 누구나'라서 전직무로) → "occupation = 사업이 겨냥하는 직무" 규칙 + 정답셋 G16 추가로 고정. 정답셋에 없던 필드의 회귀를 눈검수로 잡았고, 그 케이스를 정답셋에 편입 — 정답셋이 성장하는 구조.
