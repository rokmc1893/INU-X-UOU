# Claude–Codex 검증 핸드오프 규칙

이 폴더는 Claude가 만든 계획·결과를 Codex가 검증하고, 검증 결과를 다시 Claude가 반영하는 순환 작업의 기록소다.

## 역할

- **Claude:** 설계·계획·구현안 작성 및 검증 요청
- **Codex:** 근거, 논리, 법·절차, 수치, UX 정합성 검증
- **사용자:** 중요한 방향 변경과 최종 승인

Codex는 Claude 계획의 검증 담당이다. 검증 없이 Claude 문서를 대신 확정하거나 구현 범위를 임의로 넓히지 않는다.

## 번호 규칙

모든 교환 파일은 발신자와 무관하게 하나의 연속 번호를 쓴다.

```text
H001_CODEX_TO_CLAUDE_<주제>.md
H002_CLAUDE_TO_CODEX_<주제>.md
H003_CODEX_TO_CLAUDE_<주제>.md
```

- 번호는 세 자리 숫자이며 한 번 사용한 번호를 재사용하지 않는다.
- 다음 번호는 `HANDOFF_INDEX.md`의 마지막 번호 + 1이다.
- 같은 주제의 재검증도 새 번호를 받는다.
- 파일을 받은 쪽은 원본을 수정하지 않고 새 번호의 응답 파일을 만든다.
- 반영 완료된 왕복 문서는 `03_closed`로 옮기되, 색인 기록은 남긴다.

## 폴더

- `01_claude_to_codex`: Claude가 보낸 검증 요청
- `02_codex_to_claude`: Codex가 보낸 검증 결과
- `03_closed`: 반영과 재검증이 끝난 교환 기록

## 파일 필수 머리말

```markdown
# H00N — 제목

- 발신: Claude 또는 Codex
- 수신: Codex 또는 Claude
- 상태: 검증요청 / 검증완료 / 반영요청 / 종료
- 작성일: YYYY-MM-DD (KST)
- 응답 대상: H00N 또는 없음
- 관련 챕터: 문서명 §번호 또는 없음
- 다음 담당: Claude / Codex / 사용자
```

## Codex 검증 결과 형식

1. `판정`: 타당 / 조건부 타당 / 수정 필요 / 근거 부족
2. `확인된 사실`: 출처와 적용 범위를 함께 기록
3. `문제점`: 사실 오류, 논리 비약, 범위 과장, UX 위험
4. `수정 지시`: Claude가 바로 반영할 수 있는 문구와 챕터
5. `미확인 사항`: 추가 자료 없이는 확정할 수 없는 부분
6. `완료 기준`: 다음 검증에서 확인할 체크리스트

## 작업 흐름

```text
Claude가 H00N 검증 요청 작성
→ 사용자가 Codex에 전달
→ Codex가 H00(N+1) 검증 결과 작성
→ 사용자가 Claude에 전달
→ Claude가 반영 후 H00(N+2) 재검증 요청 작성
→ 검증 완료 시 관련 파일을 03_closed로 이동
```
