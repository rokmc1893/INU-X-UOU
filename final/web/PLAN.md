# 화면 계획 — 페이지를 나눈다

지금은 한 페이지에 다 쌓여 있다. Streamlit에 있던 다섯 화면을 **주소가 있는 페이지**로
갈라, 체크리스트에서 해당 페이지로 넘어가게 한다.

**바꾸지 않는 것**: 판정은 파이썬 API가 한다. 화면만 나눈다.

---

## 길

| 주소 | 이름 | 무엇을 보나 |
|---|---|---|
| `/` | 지금 할 일 | 체크리스트 · 이 사업 요약 · 무엇이 비었나 |
| `/예산` | ① 예산이 제대로 붙어 있나 | 공식 장부와 대조 |
| `/연계` | ② 사업끼리 겹치거나 끊기지 않았나 | 겹침 4종 · 넘기는 절차 · 관계도 |
| `/수요` | ③ 필요한 걸 해주고 있나 | 필요한 것 7가지 · 자료 찾기 · 자료 넣기 |
| `/조치` | ④ 조치 제안 | 검토서 초안 · 협의처 · 창구 |

머리에 다섯 갈래를 늘 띄워 두고, **맡은 사업은 주소에 실어** 페이지를 옮겨도 유지한다
(`/예산?사업=IC-BIO-002`). 시연 때 링크로 바로 열 수 있다.

---

## `/` 지금 할 일

지금 화면과 같되 **체크리스트 항목마다 「근거 보기」가 해당 페이지로 넘어간다**.
지금은 그 자리에서 펼쳐지는데, 자세히 보려면 페이지가 낫다.

- 맡은 사업 고르기 (주소에 실림)
- 이 사업 요약 — 해주는 것 · 예산 · 협의처 · 원문
- 이 산업에 무엇이 비었나 (막대)
- **지금 할 일 N건** — 항목마다 「지금 이렇다 → 하고 나면 이렇게 된다」

## `/예산` ① 예산이 제대로 붙어 있나

| 무엇을 | 어디서 |
|---|---|
| 일치 · 재검토 · 소관 불일치 · 못 찾음 건수 | `budget_findings` |
| **소관 불일치 표** — 사업 문서 vs 공식 장부 · 예산서 항목명 · 원문 | `dept_mismatch` |
| 금액이 어긋나는 사업 | `budget_conflicts` |
| 대조가 끝난 사업 — 금액 · 정확/느슨 | `budget_confirmed` |
| **못 한 것과 그 이유** — 장부 대조가 10건뿐 | `empty.budget` |

새로 넣을 것: **이 산업 사업 전체의 대조 상태를 한 줄 막대로**. 몇 건 중 몇 건이
확인됐는지 보이면 "10건뿐"이 숫자가 아니라 그림이 된다.

---

## `/연계` ② 사업끼리 겹치거나 끊기지 않았나

| 무엇을 | 어디서 |
|---|---|
| 정리 필요한 겹침 — 쌍 · 이유 · 두 사업 원문 | `overlaps_harmful` |
| 일부러 나란히 둔 것 / 서로 채워 주는 것 | `overlaps_intentional`, `complements` |
| 넘기는 절차가 없는 곳 — 구간별 | `handoff_breaks` |
| 산업이 다른 쌍을 몇 개 뺐는지 | `same_industry` |
| 비었을 때 그 이유 | `empty.overlaps`, `empty.handoffs` |
| **판정 기준의 출처** — A3 반려 사유 원문 | `duplicateRule` |

**새 시각화 — 관계도.** 이 사업을 가운데 두고 겹침·나란히·채워줌·끊김을 선으로 잇는다.
선 종류로 뜻을 가른다: 굵은 붉은 선 = 정리 필요, 가는 선 = 겹치지 않음, 점선 = 끊김.
지금은 목록뿐이라 "이 사업이 어디에 물려 있나"가 한눈에 안 들어온다.

## `/수요` ③ 필요한 걸 해주고 있나

| 무엇을 | 어디서 |
|---|---|
| 이 산업 자료 상태와 물어야 할 질문 | `posture` |
| 필요한 것 7가지 막대 | `needs` |
| 하나씩 — 자료 · 등급 · 원문 · 해주는 사업 · 내 사업 표시 | `needs` |
| **빈칸 → 어디서 찾나** + 정보공개청구 문안 | `/api/sources` |
| 여기서 뺀 자료 (행정 과제 / 수요 아님) | `verdict` |

**여기에 자료 넣기를 붙인다.** 빈칸을 보고 → 어디서 찾는지 알고 → 찾아서 넣으면
→ 숫자가 바뀐다. 한 페이지 안에서 한 바퀴가 돌아야 "미리 짜놓은 것"으로 안 보인다.
넣는 길 셋: 주소 · 붙여넣기 · PDF (`/api/intake/*`).

## `/조치` ④ 조치 제안

| 무엇을 | 어디서 |
|---|---|
| 검토서 초안 내려받기 + **미리보기** | `/api/draft` |
| 협의 요청 부서 · A3 3단계 검토자 | `consult`, `reviewers` |
| 한 해 창구 띠 | `/api/calendar` |
| 유도형 산업이면 근거 3종 | `inducement_evidence` |
| 이 판정을 그대로 믿으면 안 되는 이유 | 고정 |

## 만들 순서

1. **길과 머리** — 여섯 갈래 나눔, 맡은 사업을 주소에 싣기, 공통 껍데기
2. **`/예산` · `/연계` · `/수요` · `/조치`** — 지금 펼침으로 있던 근거를 페이지로 옮김
3. **관계도** (`/연계`) — 새 시각화
4. **자료 넣기** (`/수요`) — API는 이미 있음, 화면만

1·2가 되면 시연에 필요한 것이 전부 넘어온다. 3·4는 그 위에 얹는 것이다.

---

## 남는 위험

- 페이지가 다섯이라 시연에서 헤맬 수 있다 → **머리에 늘 띄우고 주소로 바로 열 수 있게** 한다
- 체크리스트에서 페이지로 넘어가면 맥락이 끊긴다 → 각 페이지 머리에 **맡은 사업 이름과
  「지금 할 일 중 몇 번째」**를 적는다
