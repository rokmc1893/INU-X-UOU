# 구현 계획 — 사용자 시나리오부터 함수까지

**푸는 문제**: 지역 산업·정책 연계 부족. 기업이 필요하다고 말한 것과 시가 하고 있는 사업이
어긋난 곳을 찾아 담당자에게 근거와 함께 넘긴다.

**우리 자리**: 조사자 A의 A3 행정 워크플로우 8단계 중 **3단계(타부서 협의·유사·중복 검토)**
하나. 그 단계의 산출 문서가 A3 원문에 「부서 협의 요청서, 유사·중복 사업 자체 검토서」로
적혀 있고, 반려 사유가 「타 부서 기존 사업과 **대상·수단·직무 동일**」이라 우리 판정 규칙과
정확히 겹친다.

**하지 않는 것**: 정책을 제안하지 않는다. 발의권은 A1상 **과(課) 단위**이고 1단계 성립
결정은 담당 과장이다. 우리는 검토서 초안과 근거만 낸다. **모든 판정은 「후보」다.**

# 1. 사용자 시나리오

## 누구

인천시 **반도체바이오과 주무관**. K-NIBRT 바이오공정 교육과정을 맡고 있다.
소관 산업은 이미 정해져 있다 — A1상 발의권이 과 단위이므로 담당자가 산업을 고를 일은 없다.

## 언제·왜 들어오나

성과평가(A3 7단계)가 끝나고 **"이 교육과정 개편안을 만들어라"**가 내려왔다.
A2 결정 달력의 **「기존사업 개편/확대」** 트랙이고, 마감은 7월 31일(성과평가 반영 제출)이다.

> **근거**: 이 경로가 가장 많다. 6대 산업 정책원장 52건 중 **이미 추진 중인 사업이
> 37건(71%)**이고 국비·공모에서 출발한 것은 11건(21%)이다 (E026·E027).
> 한계 — `status`는 조사 시점 상태이지 예산서상 「계속 vs 신규」 분류가 아니다.
> 배수로 말하지 않는다.

## 무엇을 하나 — 시간 순서

```

     → 산업이 '바이오'로 자동 설정된다
```

## 무엇을 들고 나가나

**결재문서에 붙일 검토서 초안 하나.** 그 안에 세 가지가 근거와 함께 들어 있다:

1. **협의처가 틀렸다** — 공문 보낼 곳이 중앙부처가 아니라 경제자유구역청이다
2. **정리해야 할 겹침이 있다** — GTH-B와 대상·수단·직무가 같다 (A3 실제 반려 사유)
3. **내 사업은 「사람」을 채우고 있고, 바이오에서 비어 있는 것은 「돈」 2건이다** —
   교육과정을 아무리 늘려도 그 둘은 안 채워진다

# 3. 자료가 들어오는 길

```
사람이 모은 원장 (A·B·C)
   B1 정책 포트폴리오 52건 ─┐
   P* 청년정책 카드 10건   ─┼→ fit.load.cards()  →  카드 62건
                          │      (계획 5건은 load.is_plan()으로 분리)
   B2 수요신호 78행       ──┼→ fit.load.b2()
   B3 연계근거 22쌍       ──┼→ refdata.linkages()
   A1 부서 · A2 달력      ──┼→ scenario.actors / calendar
   C9 예산검증 10건       ──┼→ refdata.budget_status_for()
   C1 성과축 7개          ──┘→ fit.axes.all_axes()
        ↓
   detect.build_edges()   →  엣지 212개 (HANDOFF · COVERS · OVERLAP 3종)
        ↓
   store.load() + add_edges()  →  Neo4j (없으면 MemoryStore로 자동 전환)
        ↓
   detect.run_rules() + budget_findings() + needs.coverage() + industry.postures()
        ↓
   화면 0~4  ·  검토서 초안
```

**LLM이 있는 곳은 `engine/extract.py` 하나뿐이다.** 원문에서 항목을 뽑는 데만 쓰고,
무엇이 겹침인지·무엇이 비었는지 고르는 일은 전부 파이썬 규칙이 한다.
원문에 없는 값은 채우지 않고 `missing_fields`에 남긴다. (테스트로 강제)

# 5. 구현 Phase

## Phase 0 — 비어 있는 이유를 화면이 말하게 하기

미래차로 돌려 보니 화면 1·2가 **통째로 비었는데 왜 비었는지 화면이 말하지 않았다.**
지금 자료로 담당자가 쓸 수 있게 만드는 단계다. **판정 규칙은 안 건드린다.**

- 화면 2가 0건일 때 → `"이 산업 사업이 N건뿐이라 겹칠 것이 없습니다"`
- 화면 1이 「못 함」일 때 → `"이 사업은 C9 예산검증 10건에 없습니다"` (사업별로)
- 화면 3에 **내가 맡은 사업이 어느 칸을 담당하는지 ★ 표시**

**완료 기준**: 미래차를 골라도 각 화면이 비어 있는 이유를 스스로 설명한다.

## Phase 1 — 출처 안내판

산업을 고르면 **어디를 봐야 하는지**를 상태와 함께 보여준다. 자동 수집은 아직 없다.

`final/scenario/sources.py` → `sources(industry) → [{name, url, what, status, note}]`
- `ok` 검색어까지 붙인 링크 · `blocked` 막힘 표시 · `manual` 정보공개청구 문구까지

**확인된 접근성 (2026-08-14)**: 기업마당 오픈API·온통청년·ELIS·KOSIS·인천시 누리집 ✅ /
인천TP·인천연구원 SSL 오류 ❌ / 지방재정365 연결 실패 ❌ / 정보공개포털 JS ❌

**완료 기준**: 산업 6개마다 출처 6곳 이상이 상태와 함께 뜬다. 막힌 곳이 `ok`면 실패.

## Phase 2 — 자료 직접 올리기 (입구 ②③)

`fetch.fetch_policy_text()` → `extract.extract_card()`는 이미 있다. 입구만 만든다.

- URL 붙여넣기 / 텍스트 붙여넣기 / 파일 올리기(PDF·HWP)
- **스캔 이미지면 실패한다고 바로 알린다** (우리가 실제로 겪은 문제)
- 올린 자료는 **세션 한정**. 원장 파일을 덮어쓰지 않고 `직접 올림` 배지를 단다

**완료 기준**: URL 하나로 카드가 생기고 기존 57건과 대조된다. 원장 파일은 변하지 않는다.

## Phase 3 — 기업마당 API (인증키 확보 후)

`final/scenario/bizinfo.py` → `search(industry, region="인천")`
기업마당 분야(금융·기술·인력·수출·판로)가 우리 지원 유형과 거의 같아 그대로 매핑된다.

**선행 조건**: 공공데이터포털에서 **사람이** 인증키 발급. `.env`로만 관리하고
코드·화면·발표자료에 **절대 노출하지 않는다.**

**한계**: 기업마당은 **기업지원사업만** 모은다. 상위 계획·실태조사·내부 문서는 없다.

## Phase 4 — Neo4j 누적 적재

지금 `store.load()`는 **매번 전체를 지우고 다시 넣는다**(`DETACH DELETE`).
자료를 계속 올리는 구조에서는 맞지 않는다.

- 전체 삭제 대신 `MERGE`로 누적
- 노드에 `source`(원장 / 직접 올림 / 기업마당)와 `added_at`
- 새 자료가 들어오면 그 노드 주변 관계만 다시 계산

**이것이 그래프DB를 쓰는 이유다** — 자료가 늘어도 관계 정의를 다시 짜지 않는다.
지금은 그 장점을 못 쓰고 있다.
