## 0. Claude가 가장 먼저 알아야 할 결론

### 최종 제품비전

> **지역산업 수요–정책 포트폴리오 정합성 설계 워크벤치**  
> 지역 현안이나 사업안을 입력하면 산업·기업·인재 수요와 기존 정책·예산을 비교해 어디가 비고, 겹치고, 끊기고, 늦는지 보여주며, 기존 사업의 보완·연결·통합과 신규·파일럿 정책을 실행·검증 조건과 함께 비교해 주는 의사결정 지원 도구다.

서비스명은 당분간 **정책핏 인천**을 사용한다. 내부 분석 기능은 `정합성 감사 엔진`이라 부를 수 있지만, 행정부서의 방어적 반응을 줄이기 위해 외부 화면에서는 `감사`보다 `진단·설계`를 사용한다.

### 첫 검증 모듈

제품구조는 여러 산업·성과목표로 확장 가능하게 설계하되, 첫 검증은 다음으로 좁힌다.

- 산업: 인천 바이오의약품
- 대상: 인천 거주 또는 인천 소재 학교 출신의 바이오·생명·화학·화공계열 전문학사·학사 졸업예정자 및 졸업 3년 이내 청년
- 직무: 바이오의약품 생산·공정·QA·QC 첫 취업
- 심층 비교사업:
  - 인천 청년도약기지 생산·품질관리 관련 트랙
  - 인천대학교 바이오의약품 제조·품질관리 양성과정
  - K-NIBRT Bio-All
- 대표 결정질문: `현재 사업들을 그대로 운영할 것인가, 역할을 재설계·연결할 것인가, 별도의 취업전환 정책이 필요한가?`

### 사용자 역할

프로젝트 소유자인 사용자는 이제 다음에 집중한다.

- 서비스 기획과 범위 통제
- 핵심 사용자 흐름·화면·PRD 설계
- 기술 스택과 AI·데이터 아키텍처 선정
- 조사팀 세 명의 산출물 통합
- 최종 MVP 항목 선택

나머지 세 명은 이 문서의 `13. 조사팀 역할분담`에 따라 실제 행정·사업·데이터 조사를 맡는다.

### 절대 혼동하지 말 것

- 이 서비스는 정책검색·개인정책추천 포털이 아니다.
- AI가 정책의 채택·폐지·예산을 자동 결정하는 서비스가 아니다.
- 공개 채용공고는 `관측된 채용신호`이지 기업의 확정 미래수요가 아니다.
- 공개데이터로 정책설계 미스매치는 진단할 수 있지만 정책의 매출·고용·정착 인과효과는 바로 증명할 수 없다.
- `자료 없음`은 `성과 0`이나 `수요 없음`이 아니다.

## 1. 아이디어가 어떻게 변했는가

### 최초 문제의식

처음에는 다음 문제를 해결하려 했다.

> 인천의 청년인재 유출과 지역 전략산업·청년정책 간 연계 부족

초기 아이디어는 산업 성장방향과 인재수요를 분석하고, 기존 정책과 비교해 공백·중복·시차·대상 불일치를 찾아 정책 보완안과 신규안을 추천하는 플랫폼이었다.

### 첫 번째 전제 수정

공식 통계와 인천연구원 자료를 검토한 결과, 최근 인천 청년을 `주민등록 순유출`로 표현하는 것은 근거와 맞지 않았다.

- **[확인된 사실]** 최근 인천 청년은 주소 기준으로 순유입되는 경향이 확인됐다.
- **[확인된 사실]** 인천 거주 청년 중 상당수가 타지역에서 근무하고, 원하는 직무와 임금 차이가 역외취업 이유로 나타난 자료가 있다.
- **[판단]** 주소이동보다 `관외취업·직주분리·지역 내 양질의 경력경로 부족`이 더 정확한 문제후보다.
- **[반대가설]** 정책연계 부족보다 임금, 기업규모, 직무 다양성, 고용안정, 통근, 조직문화, 경력전망이 더 큰 원인일 수 있다.

### 두 번째 범위 수정

이후 청년 취업만 보면 산업정책 불일치로 생기는 다른 결과를 놓친다는 문제가 제기됐다.

- 현장수요와 다른 사업으로 정책 실효성 저하
- 유행분야·중복사업 투자로 예산 비효율
- 필요한 인력·기술·판로·금융지원 지연으로 기업 경쟁력 약화
- 교육과 기업 직무수요 불일치로 인재·일자리 미스매치
- 기업·대학·연구기관·지자체 방향 불일치로 생태계 형성 저해
- 지역특성에 맞지 않는 산업육성으로 지역격차 심화
- 현장과 동떨어진 사업 반복으로 정책 신뢰 저하

따라서 최종적으로는 문제를 `청년유출 단일문제`보다 한 단계 위인 **지역산업 수요와 정책 포트폴리오의 불일치**로 재정의했다. 청년 바이오 취업은 제품 전체가 아니라 첫 번째로 증명할 구체 모듈이 됐다.

### 현재 범위 결정

> **문제정의와 제품구조는 넓게, 실제 데이터·데모·성과주장은 좁게 가져간다.**

```text
넓은 제품비전
지역산업 수요–정책 포트폴리오 정합성 설계 워크벤치

좁은 첫 증명
인천 바이오 청년 취업 관련 사업의 보완·연결·신설 판단
```

## 2. 최종 문제 정의

### 사회·정책 문제

> **인천 전략산업의 관측된 기업·인력·기술 수요 변화에 비해 정책 포트폴리오의 대상·기능·시기·지역·예산이 어디에서 비거나 겹치는지 근거와 불확실성을 함께 보여주지 못해, 정책 발의부서가 기존 사업의 유지·보완·연결·통합·종료와 신규 사업 필요성을 판단하기 어렵다.**

### 서비스가 직접 해결하는 문제

> 정책 담당자가 분산된 산업·기업·고용·교육·예산·기존사업 자료를 공통 구조로 비교하고, 정책 제안 전에 수요–대상–수단–시기–예산–성과경로의 불일치를 확인하기 어렵다는 의사결정 문제

### 직접 문제와 장기효과의 구분

```text
정책핏의 직접효과
근거 완전성·검토속도·누락탐지·결정 추적성 향상
                ↓
행정 중간효과
사업 보완·연결·통합·신설, 예산조정, KPI·평가설계 개선
                ↓
정책의 사업성과
기업 충원·매출·투자, 취업·임금·직무일치·근속
                ↓
지역 장기성과
기업경쟁력·산업생태계·지역격차·인재정착
```

마지막 두 단계는 플랫폼에 직접 귀속하지 않는다.

## 3. 아직 사실로 확정하면 안 되는 가정

1. 정책 간 연계 부족이 청년 관외취업이나 기업 성장저하의 핵심 원인이다.
2. 공개된 채용공고가 인천기업의 실제 미래 인력수요를 대표한다.
3. 현재 정책들이 실제로 서로 중복되거나 연계되지 않는다.
4. 공식 조정위원회가 존재하더라도 실무조정 기능이 약하다.
5. 정책담당자가 정합성 진단 결과로 예산·사업을 바꿀 권한과 유인을 가진다.
6. 더 높은 설계 정합성이 실제 매출·고용·취업·정착 성과로 이어진다.
7. 공개데이터가 많은 기존 강점산업이 반드시 추가지원 우선순위다.

위 문장은 모두 현재 **[가설]**이다. 조사결과가 없으면 `미확인`으로 유지한다.

## 6. 사용자의 세 가지 진입경로

### 입구 A — 기존사업을 고치고 싶어요

- 입력: 기존 사업계획서·공고·성과자료, 사업 고유목표, 예산·기간·협력기관
- 질문: 유지·보완·연결·통합·중단검토 중 무엇이 적절한가?
- 산출: 사업 정책사슬, 유사·연결사업, 누락된 수요·KPI, 변경 전후

### 입구 B — 현안부터 조사하고 싶어요

- 입력: 현안 한 문장, 지역·산업·대상, 원하는 변화
- 질문: 현안은 실제로 존재하는가? 기존 정책으로 충분한가?
- 산출: 현안 근거·반대가설, 관련 정책 전체, 공백·중첩, 보완안·신규안

### 입구 C — 신규 사업안을 검토하고 싶어요

- 입력: 신규 제안서, 상위목표, 대상·예산·기간·협력기관
- 질문: 기존사업 보완으로 해결되는가? 정말 신규성과 추가성이 있는가?
- 산출: 기존사업 대비 추가성, 실행조건, 신규·파일럿·보류 판단

### 대표 데모의 첫 화면 — 세 갈래 선택 UI가 아니다 (확정, 2026-08-13)

위 세 진입경로는 **제품의 장기 지원 범위**로 남긴다. 다만 이번 대표 데모의 첫 화면은 세 갈래를 고르게 하는 분기 UI도, 기존사업 한 건만 고르는 화면도 아니다.

> **첫 화면 = 성과 질문 + 사전 선택된 기준사업(anchor)**

```text
화면 제목  인천 바이오 생산·품질 인재양성이 실제 채용으로 이어지지 않는 단절은 어디인가?
성과 질문  교육 → 채용 전환의 단절은 어디인가?
기준사업   인천 청년도약기지 생산·품질관리 과정
분석 범위  인천 청년 / 생산·품질 직무 / 교육→채용 전환
안내문     기준사업 한 건만 평가하지 않고, 같은 대상·직무·시기에 작동하는 주변 정책과 함께 비교합니다.
주 CTA     주변 정책과 함께 진단하기
```

기준사업을 출발점으로 삼되 **주변 사업군까지 함께 진단**하고, 마지막에 기존사업의 연결·보완·통합·축소·종료와 **신규 연결장치의 필요 여부를 함께** 판정한다. 별도의 `신규안 입력 UI`는 이번 데모 범위에서 제외한다. 다만 `기존 수단으로 덮이지 않는 공백 때문에 무엇을 새로 만들어야 하는가`는 판정할 수 있어야 한다.

**명칭 주의:** 청년도약기지의 공식 과정은 바이오 전용이 아니라 **산업횡단형 생산·품질관리 과정**이다. 바이오와 연결할 때는 `바이오 포함 생산·품질 직무`처럼 표기하고, 공식 사업명을 `바이오 생산·품질관리 트랙`으로 바꾸지 않는다.

세 입구는 동일한 엔진으로 합쳐진다.

```text
현안 / 기존사업 / 신규안
          ↓
분석목적 선택: 기업성장 / 인재·일자리 / 기술 / 생태계 / 공간·형평
          ↓
근거조사 + 반대가설
          ↓
지역수요–현재정책–예산 포트폴리오 지도
          ↓
정합성 X-ray
          ↓
기존사업 보완·연결·통합안 ↔ 신규·파일럿안
          ↓
사람 검토·수정·승인
          ↓
1장 실행·검증계획서 → 원장 누적 → 분기 대시보드 → 연간 심사자료
```

## 7. 핵심 화면과 산출물

### MVP 4화면 데모 흐름 (확정, 2026-08-13)

**화면 1 — 성과 질문 + 기준사업**
한 사업을 고립시켜 평가하지 않고, 해결할 성과 문제와 분석 범위를 먼저 고정한다. (구성은 §6 참조)

**화면 2 — 정책사슬 X-ray**
기준사업과 인접 사업군을 함께 놓고 `문제 → 대상 → 수단 → 산출 → 중간성과 → 최종성과` 사슬의 단절 후보를 표시한다. 결과는 확정적 인과판정이 아니라 다음 셋 중 하나로만 표시한다.

```text
설계상 단절 후보
집행데이터 확인 필요
담당자·수혜자 검증 필요
```

**화면 3 — 수요–정책 커버리지 행렬**
같은 직무·대상·시기에서 작동하는 사업들을 비교하되, **단순 유사성을 곧바로 낭비로 판정하지 않는다.** 네 가지를 구분해 표시한다.

```text
정책 공백 후보
사업 간 인계 단절
해로운 역할중첩 후보
접근성·전문성·실험을 위한 의도적 중첩
```

**화면 4 — 판정 카드**
`유지 / 보완 / 연결 / 통합 / 신설` 중 **하나만 고르게 하지 않는다.** 주조치 + 보조조치 구조로 두고, 필요하면 축소·종료·이관·파일럿·보류도 표시한다.

```text
주조치            기존 교육사업과 취업지원사업의 인계 연결
보조조치          기업 수요 반영 방식 보완
새로 필요한 것      공동 의뢰·추천 및 성과추적 장치
새로 만들 필요가 낮은 것   유사한 교육과정 하나 더 추가
추가 검토          성과가 확인되지 않는 중첩사업의 축소·종료
근거 수준          공개자료 확인 / 집행자료 필요 / 담당자 검증 필요
```

**보조 화면 — 예산–수요 배분 지도**
문제규모·관측수요와 정책예산을 비교해 과다·과소배분 후보를 보여준다. `낭비 확정`이 아니라 확인 필요 신호다. 4화면 흐름이 완성된 뒤에만 추가한다.

### 즉시 산출물

- 현안 근거카드와 반대가설
- 정책·사업 공통 카드
- 수요–정책 포트폴리오 지도
- 공백·역할중첩·인계단절·시차·측정공백 카드
- 기존사업 보완·연결·통합안
- 신규·파일럿안
- 변경 전후 비교
- 1장 실행·검증계획서

### 누적 산출물

- 정책·사업 증거원장
- 월간 데이터 변화 알림
- 분기 포트폴리오 대시보드
- 연간 위원회·예산심사 보고서
- 이의제기·수정·결정이력

## 8. 탐지할 미스매치 유형

1. **수요 불일치:** 산업·기업·대상자의 실제 문제와 사업수단이 다름
2. **대상 불일치:** 필요한 기업·청년·지역이 지원요건에서 빠짐
3. **수단 불일치:** 원인을 해결하지 못하는 교육·시설·보조방식
4. **포트폴리오 역할중첩:** 같은 대상·기능·직무·시기에 여러 사업이 유사 역할
5. **포트폴리오 공백:** 중요 수요·단계·대상에 대응사업 없음
6. **인계 단절:** 교육→실습→매칭→채용 등 다음 단계 책임이 없음
7. **시차:** 산업수요·모집·교육·채용·예산·성과측정 시기가 맞지 않음
8. **예산 불균형:** 관측수요·문제규모에 비해 과도하거나 부족한 배분 후보
9. **성과단절:** 사업 고유 산출과 상위 정책성과를 연결하는 브리지 KPI가 없음
10. **권한·실행 불일치:** 담당부서 권한, 법적 근거, 협력기관, 재원이 없음
11. **근거·데이터 공백:** 결과를 확인할 분모·기준일·추적자료가 없음

`중복`은 유사한 문구가 있다는 이유만으로 확정하지 않는다. 역할·대상·단계·지역·시기가 실질적으로 겹치고 인계관계도 없을 때 `역할중첩 후보`로 표시한다.

## 9. 평가모델

### 공개용 핵심 원칙

- 하나의 종합점수·사업순위로 압축하지 않는다.
- 자료가 없으면 0점이 아니라 `미측정`이다.
- 높은 수료자 수가 낮은 취업·사업화·근속을 자동 상쇄하지 않게 한다.
- 가중치·자료원을 바꿨을 때 결론이 달라지는 민감도를 표시한다.

### 권장 평가 벡터

| 축 | 질문 |
|---|---|
| 수요 정합성 | 관측된 산업·기업·인재 문제를 다루는가 |
| 추가성 | 기존 사업으로 해결되지 않는 공백인가, 역할중첩인가 |
| 대상·지역 정합성 | 필요한 기업·사람·군구에 도달하는가 |
| 시기 정합성 | 산업수요·채용·교육·예산·성과주기가 맞는가 |
| 예산 비례성 | 문제규모·수요와 예산의 과다·과소배분 후보가 있는가 |
| 실행 가능성 | 권한·법·재원·협력기관이 있는가 |
| 측정 준비도 | 분모·기준일·비교설계·추적주기·실패기준이 있는가 |
| 근거 신뢰도 | 직접성·최신성·세분성·원문·기관확인 상태가 충분한가 |

### 값 상태

```text
OBSERVED              실제 관측
DEFINED_NOT_REPORTED  KPI는 있으나 값 미공개
NOT_DEFINED           KPI 자체 없음
NOT_COLLECTED         기관도 미수집
ACCESS_REQUIRED       기관협약 필요
STALE                 갱신기한 경과
CONFLICTING           출처·정의 충돌
NOT_APPLICABLE        사업유형상 해당 없음
UNKNOWN               상태조차 판단 불가
```

## 10. AI·규칙·사람 역할분담

| 단계 | LLM | 규칙·일반분석 | 사람 |
|---|---|---|---|
| 문서처리 | 목표·대상·수단·KPI 후보 추출 | URL·문서ID·해시·버전 저장 | 원문 의미 확인 |
| 분류 | 산업·직무·역량 매핑 후보 | 승인된 KSIC·KECO·NCS 교차표 적용 | 애매한 매핑 승인 |
| 진단 | 공백·중첩·시차·반대가설 후보 | 4값 규칙과 계산 | 예외·맥락·실행성 판단 |
| 처방 | 보완·연결·통합·신규안 초안 | 권한·예산·시기·필수필드 게이트 | 정책 선택과 책임 |

LLM에 금지하는 일:

- 출처 없는 사실 보완
- 미공개 기업수요·성과 추정
- 정합성 점수 직접 생성
- 사업폐지·예산삭감·지원자격 자동결정
- 승인되지 않은 분류매핑의 확정 사용

모든 사실문장은 정확한 원문 문단·페이지·URL로 돌아갈 수 있어야 한다.

### 가장 중요한 데이터 자산

단일 API가 `정책–산업 미스매치`를 주지 않는다. 핵심은 다음의 교차표와 버전관리다.

```text
KSIC 산업 ↔ KECO 직업 ↔ NCS 역량 ↔ 대학 학과 ↔ 정책 자체 태그
```

LLM은 매핑 후보를 만들 수 있지만 사람이 승인하기 전에는 확정판정에 쓰지 않는다.

### 최소 증거원장

```text
source_document     공식 URL·발행일·수집일·해시·라이선스·버전
evidence_span       페이지·표·문단·증거등급·사람확인
policy_version      유지되는 정책ID와 연도별 버전
policy_element      문제·대상·수단·기간·예산·KPI·권한
demand_signal       지역·산업·직무·기간·값·분모·대리한계
```

## 14. 세 명이 반드시 공유할 작업규칙

### 공통 증거 컬럼

모든 파일에서 최소 다음을 유지한다.

```text
source_url
publisher
document_title
published_at
retrieved_at
page_or_section
raw_quote_or_value
claim_type        FACT / INFERENCE / HYPOTHESIS / UNVERIFIED
evidence_grade    A / B / C / D / U
coverage_limit
human_verified
```

### 증거등급

- A: 공식 원문·행정통계, 직접측정, 최신, 분모·기간·위치 명확
- B: 공식 1차 자료지만 집계·기간·세분 제약
- C: 공식기관 자체발표 또는 신뢰 가능한 2차 연구
- D: 채용공고·보도사례·오래된 대리지표
- U: 원문·위치 미확인, 사실근거 사용 금지

### 충돌 처리

- 최신 자료가 과거 자료를 자동 무효화하지 않는다. 정의·기간 차이를 기록한다.
- 자료가 충돌하면 한쪽을 숨기지 않고 `CONFLICTING`으로 전달한다.
- 데이터가 없다는 이유로 공백·실패·수요없음을 확정하지 않는다.
- 담당자 구두설명은 확인일·역할·질문·답변 범위를 기록하고 공식문서와 구분한다.

기존 사업을 고려했는지는 다음 상태로만 기록한다.

```text
EXPLICIT                 신규·개편 문서에 비교한 기존사업과 판단이 명시됨
REFERENCED               기존사업 이름은 언급됐지만 비교·판단은 없음
INFERRED                 조사자가 정황상 고려했을 가능성을 추론함
NOT_PUBLICLY_VERIFIABLE  공개자료로는 확인할 수 없음
```

`검색 결과가 없음`을 `기존사업을 고려하지 않음`으로 바꾸지 않는다.

### 조사결과와 제품 입력의 연결

| 행정 주체·권한·캘린더 | 사용자 역할, 진입시점, 실행 가능성 게이트, 담당·기한 |
| 사업 인벤토리 | 정책카드, 정책사슬 X-ray, 기존사업 추가성 비교 |

## 15. 3일 협업 일정

### Day 1 — 사실지도 만들기

공통 30분:

- 산업·지역·기간·정책결정 단위 합의
- `정책 × 대상 × 기능 × 지역 × 시점` 분석단위 고정
- 공통ID와 증거 컬럼 확정

병렬작업:

- 조사자 1: 조직·담당·공식절차·연간 의사결정 캘린더 초안
- 조사자 2: 관련 사업 10~20개 인벤토리와 산업수요 원자료
- 조사자 3: 일곱 성과항목 데이터 가용성 1차 채점과 표본 호출
- 사용자: 사용자 흐름·화면·스택 후보·공통 데이터계약

Day 1 종료 게이트:

- 실제 담당 역할 후보가 없는 정책은 `owner_unverified`
- 원문이 없는 사업은 포트폴리오 확정판정에서 제외
- 실제 데이터 표본을 못 얻은 성과항목은 MVP 후보에서 보류

### Day 2 — 서로 연결하고 반박하기

- 조사자 1의 의사결정 단계에 조사자 2의 실제 사업을 배치
- 조사자 2의 수요–정책 후보를 조사자 3이 데이터로 검증 가능한지 판정
- `중복 아닌 유사사업`, `데이터 없는 공백`, `유행신호` 음성사례를 최소 하나씩 선정
- 사용자는 수요–정책 행렬, 예산–수요 지도, X-ray 화면에 필요한 필드를 확정

Day 2 종료 게이트:

- 서비스가 개입할 실제 정책결정 한 건
- 그 결정을 내리는 역할과 시기
- 비교할 실제 사업 최소 3건
- 검증 가능한 1차 성과항목과 데이터 표본
- 규칙으로 판정할 수 없는 항목과 사람검토 항목

### Day 3 — MVP 항목 선정과 제품 인계

- 조사자 3이 일곱 항목을 최종 채점하고 PRIMARY·SECONDARY·BACKGROUND·POST-MVP로 구분
- 조사자 1이 실제 의사결정 워크플로우·담당·캘린더 확정본 제출
- 조사자 2가 정책 포트폴리오·수요행렬·공백·중첩 후보 확정본 제출
- 사용자가 화면과 기술구조에 매핑하고 MVP Go/No-Go 결정

## 16. 현재 권고하는 3일 MVP

### 범위

- 인천 바이오의약품
- 2025~2026 취업·교육·기업지원 정책 10~20건 얕은 구조화

### 산출물

1. 수요–정책 커버리지 행렬
2. 예산–수요 배분 지도와 공백·중첩 후보
3. 핵심 3개 사업의 정책사슬 X-ray
4. 기존사업 보완·연결안과 신규 파일럿안을 비교한 1장 실행·검증계획서

### 성능검증

- 수작업 정답 대비 정책필드 추출 정확도
- 핵심 사실의 원문 인용률
- 근거 없는 주장률·환각률

- 수작업 대비 검토시간과 누락항목 변화
- 규칙·가중치·자료원을 바꾼 민감도

### 검증하지 않는 것

- 실제 취업·근속 증가
- 기업 매출·투자·고용 증가
- 청년 순유출 감소
- 기관 도입 의향
- 기업의 확정 미래 채용수요

## 18. 알려진 정책주기 — 반드시 현장검증할 잠정안

아래는 공개자료를 조합한 **공식절차+추론의 혼합**이다. 실제 업무순서와 마감은 조사자 1이 확인해야 한다.

```text
기업·청년·산업 현안 또는 중앙공모·시장방침 감지
        ↓
소관 현업부서가 사업·계획 초안 및 필요자료 작성
        ↓
관련 부서·수행기관 협의, 상위계획·유사사업·법·예산 검토
        ↓
필요 시 위원회·용역·공모·보조사업자 선정 절차
        ↓
예산담당 심사와 시장 예산안
        ↓
시의회 상임위→예결위→본회의
        ↓
공고·협약·위탁·집행
        ↓
중간점검·결산·성과평가
        ↓
차년도 시행계획·본예산·추경·사업개편 반영
```

공개자료에서 보이는 주기:

- 청년정책 시행계획·전년도 실적 심의: 통상 연초 1~2월 공개 사례
- 차년도 본예산: 상반기 이전부터 사업근거·성과를 준비하고 하반기 조정, 시의회 제출 후 11~12월 심사
- 추경: 2026년 의회계획에는 4월·9월 창구가 보임
- 서비스 데이터주기: 주간 신호감지 / 월간 운영자료 / 분기 포트폴리오 검토 / 반기 중간성과 / 연간 계획·예산

관련 공식자료: [청년정책조정위원회](https://youth.incheon.go.kr/participation/committee.jsp), [인천시의회 연간계획](https://www.icouncil.go.kr/main/activity/plan_2026.jsp), [주민참여예산 절차](https://www.incheon.go.kr/budget/BUD010201)

정책을 매주 바꾼다는 의미가 아니다. 주간은 신호, 월간은 반복성, 분기는 조정, 반기·연간은 성과·예산 판단이다.

## 20. 과장 금지 표현

| 피해야 할 표현 | 사용할 표현 |
|---|---|
| 실시간 기업 수요 | 공개공고에서 관측된 최근 채용신호 |
| 정책 중복 확정 | 역할중첩 후보, 담당부서 확인 필요 |
| 정책 공백 확정 | 공개자료에서 미탐지 또는 공백 후보 |
| 예산 낭비 | 수요·대상 대비 중첩·과소·과다배분 확인 필요 신호 |
| 정책효과가 낮다 | 성과 미측정 또는 비교설계 부족으로 효과 판단 불가 |
| 청년유출 원인을 확인 | 여러 원인가설 중 정책설계와의 연결 여부를 점검 |
| AI가 정책 결정 | AI는 근거추출·비교·대안 초안, 규칙과 담당자가 판정·승인 |
| 개인정보로 취업 검증 | 법적 근거·협약을 갖춘 익명집계·동의 코호트로 후속 확장 |
| 모든 신규사업은 투자심사·중기계획 대상 | 신설은 사업 유형·규모에 따라 여러 사전 절차가 붙는다 |
| 모든 신규안은 법적으로 유사·중복 검토 의무 | 이 중 **일부** 절차가 기존 제도와의 중복·누락을 명시적으로 검토한다 |
| 유사사업은 곧 낭비 | 해로운 역할중첩 후보와 **의도적 중첩**(접근성·전문성·실험)을 구분한다 |
| X-ray가 인과관계를 확정 | 설계상 단절 **후보**이며 집행데이터·담당자 검증이 필요하다 |
| 지자체 세출 대부분이 계속사업 | **인천 청년정책 포트폴리오에서는** 계속·확대가 85.5%다 (전국 일반화 금지) |
| 청년도약기지 바이오 트랙 | 청년도약기지 **생산·품질관리 과정** (산업횡단형, 바이오 전용 아님) |

### 법·절차 관련 안전한 설명

- 모든 신규사업이 투자심사 대상인 것은 아니다. 법상 재정투자사업 중 금액·유형 기준에 해당하는 사업이 대상이며 제외사업도 있다.
- 투자심사 대상사업은 원칙적으로 중기지방재정계획과 연계되지만, 이를 모든 신규 정책사업의 일률적 선행절차로 표현하면 안 된다.
- 유사·중복 검토는 모든 신규안에 동일하게 부과되는 보편적 단일 절차가 아니다.
- 지방보조사업, 사회보장제도 신설·변경, 일부 지방재정영향평가 대상에서는 중복·누락 또는 유사·중복 검토가 명시적으로 요구된다.

발표에서는 법조문을 길게 설명하지 말고 다음 한 문장만 쓴다.

> 신설은 사업 유형·규모에 따라 여러 사전 절차가 붙으며, 일부 절차는 기존 제도와의 중복·누락을 명시적으로 검토합니다.

## 21. Claude에게 요청할 다음 작업

이 문서를 받은 Claude는 다음 순서로 이어가는 것이 좋다.

1. 조사자 1~3의 템플릿이 실제 팀에서 사용할 만큼 명확한지 검토
2. 사용자의 기술 스택 후보에 맞춰 공통 데이터계약과 화면별 필드를 정의
3. 조사결과가 들어오면 사실·추론·가설을 다시 분리
4. 일곱 성과항목 선택표를 기준으로 MVP PRIMARY 1개와 SECONDARY 1개 결정
5. 실제 정책제안 시점·담당·워크플로우에 MVP 진입점을 고정
6. 60초 데모 흐름과 1장 실행·검증계획서 템플릿 작성
7. 3일 프로토타입 범위를 넘는 기능을 백로그로 이동

Claude가 지켜야 할 제약:

- 최신 결정은 `범용 포트폴리오 워크벤치 + 좁은 바이오 청년취업 첫 모듈`이다.
- 과거 문서의 `청년정책담당관이 최종 고객으로 확정`이라는 표현은 재검증 대상이다.
- 해결책을 정책검색·개인추천 서비스로 되돌리지 않는다.
- 성과데이터가 없을 때 추정값을 만들지 않는다.
- 사용자에게 이미 확정한 결정을 반복 질문하지 않는다.
- 범위를 넓히더라도 3일 데모는 하나의 실제 결정에 집중한다.
