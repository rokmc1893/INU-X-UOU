## 0. LLM은 언제 도는가 — 한 눈에

**LLM은 `engine/extract.py` 한 파일에만 존재한다.** 아래 4개 지점 외에는 절대 호출되지 않는다.

| # | 실행 지점 | 트리거 | 모델 | 호출 수 |
|---|---|---|---|---|
| 1 | 정책 원문 배치 추출 | `python -m engine.extract` (터미널) | gpt-4o-mini | 정책 1건당 1~2회 (계약 위반 시 1회 재교정) |
| 2 | 정책 풀 변환 | `python -m engine.pool 바이오` (터미널) | gpt-4o-mini | 원장 1행당 1~2회 |
| 3 | 라이브 재추출 | 화면 2의 🔴 버튼 클릭 | **gpt-4o** | 1회 |
| 4 | URL 수집 | 사이드바 "가져와서 분석에 추가" | gpt-4o-mini | 1회 |

**LLM이 절대 돌지 않는 곳** — 이게 이 제품의 설계 핵심이다.

```
앱 시작           카드는 이미 JSON 파일 (data/cards/)        → LLM 0회
판정 5종          detect.py — 규칙만. import openai 없음     → LLM 0회
그래프 적재       store.py — Cypher CREATE                   → LLM 0회
정확도 채점       evaluate.py — 문자열 비교                  → LLM 0회
폴백 HTML 생성    snapshot.py                                → LLM 0회
```

**즉 앱을 켜고 4화면을 전부 둘러보는 동안 LLM 호출은 0회다.** 3·4번 버튼을 누를 때만 돈다.
이것이 "판정에 AI가 개입하지 않는다"의 물증이다 — 네트워크를 끊어도 판정은 동일하게 나온다.

## 시나리오 1 — 심사위원 앞 시연 (내일 발표)

**주체:** 발표자 · **소요:** 150초 · **상태:** 작동 확인됨

| 단계 | 사용자 행동 | 무엇이 도는가 | LLM |
|---|---|---|---|
| 1 | 앱 접속 | `init()` — 카드 JSON 로드 → `build_edges()` 규칙으로 엣지 생성 → Neo4j에 Cypher `CREATE` 적재 → `run_rules()` 판정. 결과는 `@st.cache_resource`로 캐시 | ✗ |
| 2 | 화면 1 | 판정 5종 카운트, 예산 달력(A2 원장 — 필요문서·심사 경로 포함) | ✗ |
| 3 | 화면 2 | 결재란 사슬 HTML 렌더 — HANDOFF 엣지 유무로 실선/절단선 결정. 엣지는 원문 추출 + **조사자 B의 B3 확인 인계**에서 온다 | ✗ |
| 4 | 🔴 라이브 버튼 | `extract_card(model="gpt-4o")` → 저장 카드와 나란히 비교 | **✓ 1회** |
| 5 | 사이드바에서 범위를 "+바이오"로 | `init("바이오")` 재실행 — 풀 카드 16장 결합 → 판정 재계산 → Neo4j 재적재 | ✗ |
| 6 | 화면 3 Cypher expander | `detect.CYPHER` 5종을 그대로 출력. 판정 계산은 파이썬이 한다 — 질의를 직접 돌리면 행 수가 더 많다(대상·직무 비교가 앱 계층) | ✗ |
| 7 | 화면 4 다운로드 | `draft_report()` — findings를 마크다운 문자열로 조립 | ✗ |

**실패 대비 3단 폴백**
1. Neo4j 죽음 → `MemoryStore` 자동 전환, 판정 동일 (사이드바에 스토어명 표시)
2. API 죽음 → 4번 버튼만 실패, 화면에 폴백 문구. 나머지는 정상
3. 앱·인터넷 전부 죽음 → `data/demo_fallback.html`을 브라우저로 열기

## 시나리오 2 — 공무원이 분석 범위를 바꿔 본다

**주체:** 주무관 · **상태:** 작동하나 **결과 해석에 주의 필요**

사이드바 selectbox를 "청년일자리 + 바이오"로 바꾸면:

| 범위 | 정책 | 지원 공백 | 인계 공백 | 조정 필요 중복 | 의도적 병행 | 보완 관계 |
|---|---:|---:|---:|---:|---:|---:|
| 청년일자리 | 10건 | 3 | 29쌍 | **1** | 1 | 5 |
| +바이오 | 26건 | **0** | 72쌍 | **2** | 2 | 6 |

*(2026-08-13 심야 실측. Phase 6의 수단 축 도입 + B3 연계근거 주입 후 값이다.)*

**이 변화가 이 제품의 핵심 서사다.** 청년 포트폴리오만 보면 바이오가 "공백"인데, 산업 풀을 결합하면 K-NIBRT 교육과정이 그 수요를 이미 커버하고 있다 — **문제는 공백이 아니라 부처 경계에서 끊긴 인계**였다.

**정직하게 붙일 한계 3가지**
- 인계 공백 29·72쌍은 `combinations(cards, 2)` O(N²) 산출이고 `전직무`가 모든 직무와 겹치도록 설계돼 사실상 전수 매칭이다. 정책 100건이면 1,000쌍 단위가 되어 **읽을 수 없는 목록**이 된다. 우선순위 스코어링·상위 N건 컷이 실사용 전제다.
- 같은 부서끼리인 쌍은 Phase 6에서 **"협조공문이 아니라 부서 내 조정"**으로 구분했고, A3의 고정 검토자(청년정책담당관·교육협력담당관·평가담당관)를 함께 표시한다.
- `조정 필요 중복`이 두 범위 모두 **0건**이다. 현 코퍼스에 대상 요건이 완전히 겹치는 쌍이 없어서이며, 만들어 넣지 않았다. 이 지표는 지금 코퍼스로는 판별력이 없다.

## 시나리오 3 — 공무원이 새 정책을 URL로 넣는다

**주체:** 주무관 · **상태:** 작동하나 **세션 한정**

```
URL 입력 → fetch.py: requests.get → html.parser로 태그 제거 → 메타헤더 부착
        → extract.py: LLM 추출 + 기권 계약 + 인용 실재 검증   ← LLM 1회
        → session_state에 카드 보관 (파일 저장 안 함)
        → build_edges + run_rules 재계산
        → 카드 구성이 바뀌었으므로 Neo4j 재적재 (Cypher CREATE)
        → 화면 2·3에 반영
```

**되는 것:** 공개 웹페이지 URL이면 즉석에서 분석에 합류한다. Neo4j에도 실제로 들어간다(D-022에서 고침).
**안 되는 것:** 새로고침하면 사라진다. HWP·PDF·내부 문서는 못 읽는다. 저장 기능이 없다.
**왜 세션 한정인가:** 시연 중 잘못된 URL로 검증된 코퍼스가 오염되면 정확도 수치까지 흔들린다. 영구 저장은 사용자·권한 개념이 함께 필요하며 지금 구조에 둘 다 없다.

## 시나리오 4 — 관리자가 정책 풀을 갱신한다 (배치)

**주체:** 개발자/운영자 (공무원 아님) · **상태:** 작동

```bash
python -m engine.pool 바이오      # B1 원장 → 의사원문 → LLM 추출 → data/pool/cards/*.json
python -m engine.evaluate         # 정답셋 37건 재채점 → data/results.json
python -m engine.snapshot         # 폴백 HTML 재생성
```

`pool.py`는 B1 원장(24열 CSV)의 각 행을 `# key: value` 메타헤더가 붙은 의사원문 텍스트로 바꾼 뒤 `extract_card()`에 넣는다. 이때 `UNKNOWN` 값은 줄 자체를 생략하고(원문에 없음 = 기권 대상), `CONFLICTING:` 수치는 "출처 간 수치 충돌로 미기재"로 치환한다 — 출처가 다투는 숫자를 카드에 넣지 않기 위해서다.

**갱신 = 이 명령 재실행이 전부다.** 스케줄러(작업 스케줄러/cron)에 걸면 백그라운드 업데이트가 되지만, **스케줄러 등록 자체는 구현돼 있지 않다.**

**주의:** 풀 카드 16장 중 stage가 null인 것이 10장, occupation이 null인 것이 8장이다. 시설 구축·기업 R&D처럼 사람의 취업 단계를 다루지 않는 사업이라 사슬에 참여하지 않는 게 맞지만, 화면에는 "사슬 밖"으로만 표시된다.

## 시나리오 5 — 공무원이 신규사업(안)을 넣는다 ✅ **Phase 6에서 구현**

3단계 업무의 본론이다. 사이드바 ①번 칸에 사업 개요를 붙여넣으면 기존 `extract_card()` → 규칙 → **내 사업 ↔ 기존 사업** 대조가 돌고, 검토서 초안 맨 앞에 「1. 검토 대상 신규사업(안)」 절이 생긴다.

**실증 (「청년 면접복장 지원」 신규안 투입):** 드림나래(현물·물품대여)와는 **조정 필요 중복**, 드림체크카드(현금지원)와는 **보완 관계**로 정확히 갈린다. 수단 축 도입 전에는 정반대로 판정했다.

**여전히 안 되는 것:**

| 필요한 것 | 현재 | 격차 |
|---|---|---|
| 텍스트 붙여넣기 입력 | **구현됨** | — |
| HWP·PDF 업로드 | 없음 | 파서 필요 |
| 저장 | 세션 한정 (새로고침 시 소멸) | 사용자별 저장소 필요 |
| 로그인·권한 | 코드 0줄 | 인증 필요 |
| 결재 서식 출력 | 마크다운 `.md` | HWP 서식 필요 |

**기존 정책을 영구 추가하려면(운영자용):** `data/policies/raw/`에 `P0NN_이름.txt` 명명 규칙 + `# source_url:` 메타헤더를 손으로 맞춰 넣고 `python -m engine.extract` 실행. 공무원이 할 수 있는 일이 아니다.

## 기술 스택 — 무엇이 무엇을 하는가

| 계층 | 기술 | 역할 | LLM |
|---|---|---|---|
| 수집 | `requests` + `html.parser` | URL → 원문 텍스트 | ✗ |
| 추출 | **OpenAI API** (gpt-4o-mini / 시연 gpt-4o) | 원문 → 정책카드 JSON. 기권 계약·인용 실재 검증 | **✓ 유일** |
| 저장 | Neo4j (주) / MemoryStore (폴백) | 속성 그래프. Cypher `CREATE`로 노드·엣지 적재 | ✗ |
| 판정 | 순수 파이썬 (`itertools.combinations`) | 규칙 **5종**. 동일 논리 Cypher 5종을 화면에 노출 | ✗ |
| 채점 | 순수 파이썬 | 정답셋 37건 대비 4지표 | ✗ |
| 화면 | Streamlit | 4화면 + 검토서 초안 다운로드 | ✗ |
| 폴백 | 정적 HTML 생성 | 의존성 0으로 4화면 재현 | ✗ |

**모델을 둘로 나눈 이유(D-021):** 공개하는 정확도 지표는 **전부 gpt-4o-mini 산출물로 측정**했다. 즉 더 낮은 모델의 성적을 공개한다. 라이브 버튼만 gpt-4o를 쓰는 것은 정확도 과시가 아니라 시연 중 응답 안정성 때문이다.

**비용:** 정책 1건 추출 = 최대 2호출. 풀 52건 전체 갱신 1회가 1달러 미만. **비용은 도입 장애물이 아니다.**

## 지금 못 하는 것 (요약)

| 영역 | 판정 | 이유 |
|---|---|---|
| 공무원 PC 직접 설치 | **불가** | Python 설치·`pip install`·터미널 필요. 서버 배포용 Dockerfile·인증·프록시가 없음 |
| 자기 부서 사업 **영구 저장** | **불가** | 신규안 대조는 되지만 세션 한정이다. 시나리오 5 참조 |
| 여러 부서 동시 사용 | **불가** | `@st.cache_resource`가 전 세션 공유이고, `store.load()`가 `MATCH (n) DETACH DELETE n`으로 공유 그래프를 통째로 지우고 다시 쓴다 |
| 감사기록·이력 | **불가** | 인증·로깅 코드 0줄 |
| 결재 상신 | **불가** | 출력이 마크다운. 문서번호·수신·발신·결재란 없음 |
| 망분리 환경 LLM | **미확인** | 인천시가 외부 생성형 AI API 호출을 어떤 절차로 심의하는지 확인하지 않았다. **"망분리라 불가능하다"고 단정하지 말 것** — 확인이 필요한 전제로 둔다 |

**부서 1곳이 실제로 쓰기까지: 개발만 4~6주** (서버 배포·인증 / 입력·저장 UI / 다중 사용자 격리 / 판정 규칙 정밀화 / HWP 서식 / LLM 경로 결정). 보안심사·개인정보 영향평가 등 조직 절차 기간은 별도이며 그쪽이 더 길 가능성이 높다.
