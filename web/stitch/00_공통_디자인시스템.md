# Stitch 핸드오프 — 「정책핏 인천」 웹 5화면

`final/` 스트림릿 확정본을 Next.js로 다시 짓기 위한 **디자인 발주서**다.
Stitch에는 **한 화면씩** 넣는다. 아래 5개 파일을 순서대로 쓴다.

| 파일 | 화면 |
|---|---|
| `01_화면0_무엇을보는가.md` | 0 무엇을 보는가 |
| `02_화면1_예산이새는가.md` | 1 예산이 새는가 |
| `03_화면2_사업끼리이어지는가.md` | 2 사업끼리 이어지는가 |
| `04_화면3_산업수요와맞는가.md` | 3 산업 수요와 맞는가 |
| `05_화면4_조치제안.md` | 4 조치 제안 |

각 파일은 **그 자체로 완결**돼 있다(공통 디자인 시스템이 파일마다 들어 있음).
파일 안의 코드블록 전체를 복사해 Stitch 프롬프트에 붙여넣으면 된다.

## 넣은 데이터는 전부 실제 판정 결과다

수치·사업명·판정 문구는 [web/data/policyfit.json](../data/policyfit.json)에서 그대로 뽑았다.
Stitch가 임의의 더미 데이터를 지어내면 화면 밀도가 실제와 달라지므로 **실데이터를 프롬프트에 박아 둔다.**

## Stitch에 맡기지 않는 것

- 판정 로직 (파이썬이 이미 끝냈다. 웹은 JSON을 렌더링만 한다)
- 상태관리·API·인증·DB (없다)
- 모바일 레이아웃 (발표장 노트북 1회 시연이 목적. 데스크톱만)

## 받은 결과를 쓸 때 주의

Stitch 산출물은 **시각 레퍼런스**로 쓰고, 아래 3개는 코드에서 반드시 다시 확인한다.

1. 모든 판정에 「후보」 표기가 남아 있는가 (조사자 C 실패기준)
2. 각 화면 하단 「이 축의 한계」 문단이 지워지지 않았는가
3. `판정 못 함` 3축이 화면에서 삭제되지 않았는가
