# 지역문제 해결형 AI 해커톤 공통 평가 루브릭

> 버전: 1.0  
> 기준 문서: `introduce.md` (2026-08-12 배포본)  
> 적용 대상: 울산 U1~U5, 인천 I1~I5의 아이디어·콘셉트·프로토타입·최종 발표  
> 목적: 사람 심사자, Claude, Codex 등 서로 다른 평가자가 같은 증거와 같은 산식으로 평가하도록 한다.

## 1. 공식 기준과 고정 규칙

공식 배점은 아래와 같으며 임의로 바꾸지 않는다.

| 공식 항목 | 배점 | 이 루브릭의 세부 항목 |
|---|---:|---:|
| AI 기술 활용성·완성도 | 30 | AI1~AI6, 각 5점 |
| 지역문제 해결성 | 30 | REG1~REG6, 각 5점 |
| 창의성·혁신성 | 30 | CRE1~CRE6, 각 5점 |
| 발표 전달력 | 10 | PRE1~PRE2, 각 5점 |
| **합계** | **100** | **20개 항목** |

### 동점 처리

**같은 배점이어도 표에서 위에 있는 항목의 우선순위가 더 높다.** 총점 계산에서는 AI·지역문제·창의성이 각각 동일한 30점이지만, 총점 동점 시에는 표의 위쪽 항목부터 차례로 비교한다. 이 우선순위는 아래와 같이 확정한다.

```text
AI 기술 활용성·완성도 > 지역문제 해결성 > 창의성·혁신성 > 발표 전달력
```

1. 총점이 높은 팀
2. 총점 동점이면 AI 기술 활용성·완성도 점수가 높은 팀
3. 다시 동점이면 지역문제 해결성 점수가 높은 팀
4. 다시 동점이면 창의성·혁신성 점수가 높은 팀
5. 다시 동점이면 발표 전달력 점수가 높은 팀
6. 네 항목까지 모두 같으면 `완전 동점 — 운영진 결정 필요`로 기록한다.

즉, 총점이 같은 두 팀은 `[AI, 지역, 창의, 발표]` 벡터를 왼쪽부터 하나씩 비교하며, 처음으로 점수 차이가 나는 항목이 높은 팀이 수상 우선권을 갖는다. 임의의 소수점, 평가 확신도, 위험 플래그를 추가 동점 기준으로 쓰지 않는다.

## 2. 에이전트 필수 평가 원칙

아래 규칙에서 `반드시`는 선택 사항이 아니다.

1. **평가 단계부터 선언한다.** `IDEA`, `CONCEPT`, `PROTOTYPE`, `FINAL` 중 하나를 고른다.
2. **증거를 먼저 추출하고 나중에 채점한다.** 모든 점수에는 확인한 증거 ID와 판정 이유를 붙인다.
3. **제출물에서 확인되지 않은 기능·성능·협력·데이터를 추정하지 않는다.** 제목, 목업, 채팅 화면만 보고 실제 AI 구현을 인정하지 않는다.
4. **계획과 구현을 구분한다.** “할 예정이다”는 작동 증거가 아니다. 다만 IDEA·CONCEPT 단계에서는 아래 단계별 기준에 따라 설계 준비도로 평가한다.
5. **사실·팀의 주장·평가자의 추론·미확인 사항을 구분한다.** 수치, 정확도, 사용자 반응, 데이터 규모를 만들어 내지 않는다.
6. **점수는 0~5 정수만 사용한다.** 보너스, 재량 가감점, 소수점은 금지한다.
7. **같은 장점을 중복 가점하지 않는다.** 같은 결함을 여러 항목에서 감점할 때도 각 항목에 미친 별개의 영향을 설명한다.
8. **최신·고가 모델, 코드량, API 호출량, 기능 수 자체에는 가산점을 주지 않는다.** 문제에 맞는 선택과 검증된 가치가 중요하다.
9. **다른 팀 점수나 수상 팀 수에 맞춰 점수를 보정하지 않는다.** 각 팀을 절대 기준으로 독립 평가한다.
10. **평가자가 외부에서 아는 사실로 팀의 증거 공백을 메우지 않는다.** 별도 사실 검증을 했다면 `외부 검증`으로 분리하고 팀이 제시한 증거처럼 취급하지 않는다.
11. **같은 단계의 결과끼리만 비교한다.** IDEA 80점과 FINAL 80점은 의미가 다르다.
12. **공식 순위에 사용할 수 있는 점수는 FINAL뿐이다.** 앞 단계 점수는 현재 준비도와 개선 우선순위를 위한 예비점수다.

### 금지되는 추론 예시

- 채팅 UI가 있으므로 LLM 또는 RAG가 실제 연결됐다고 추정
- 지도 화면이 있으므로 실시간 지역 데이터가 연결됐다고 추정
- “정확도 95%”라는 문구만으로 검증 결과를 인정
- 지역 기관 로고가 있으므로 협약·데이터 사용 허가가 있다고 추정
- 지역명만 들어갔으므로 지역 맞춤 서비스라고 판정
- AI로 발표자료를 작성했으므로 서비스가 AI를 활용했다고 판정

## 3. 평가 단계

모든 단계에서 100점 구조는 유지하되, `현재 단계에서 확인 가능한 준비도`를 평가한다. 앞 단계에서 받은 높은 점수는 최종 구현 점수를 보장하지 않는다.

| 단계 | 평가 목적 | 기본 증거 | AI4·AI5 해석 | PRE1·PRE2 해석 |
|---|---|---|---|---|
| `IDEA` | 여러 아이디어 중 개발할 안을 고르고 치명적 가정을 찾음 | 문제 정의문, 지역 근거, 대상 사용자, 기존 대안 비교, 사용자 흐름, AI 입출력, 데이터 목록, KPI, 위험·검증 계획, 화면 초안 | 구현 그 자체가 아니라 구현 준비도와 핵심 기술 가정의 검증 가능성을 본다. 작동하는 소규모 기술 실험이 없으면 AI4는 최대 4점, 수행된 초기 검증이 없으면 AI5는 최대 4점 | 아이디어 설명의 논리, 콘셉트 시트·도식·예상 데모 시나리오의 명확성을 본다 |
| `CONCEPT` | 설계가 프로토타입 개발에 들어갈 만큼 구체적인지 판단 | 아키텍처, 데이터 스키마, 인터페이스, 와이어프레임, 수용 기준, 테스트셋·평가 계획, 운영 주체 | 핵심 컴포넌트와 연결 규격이 구체적이어야 3점 이상. 실행 가능한 핵심 흐름이 없으면 AI4는 최대 4점 | 중간 설명 자료와 프로토타입 시나리오의 전달력을 본다 |
| `PROTOTYPE` | 핵심 사용자 흐름과 AI 기능이 실제 작동하는지 판단 | 실행 화면, 코드·로그, 실제 API 출력, 테스트 사례, 오류 사례, 실·가상 데이터 표시 | 입력→AI 처리→출력→사용자 행동이 추적되어야 3점 이상 | 시연 흐름, 결과 해석, 백업 자료의 준비도를 본다 |
| `FINAL` | 공식 심사와 순위 결정 | 마감 전 제출본, 7분 발표, 실제 시연 또는 검증 가능한 녹화, 결과·출처, 2분 질의응답 | 계획보다 실제 작동·측정 증거를 우선한다 | 실제 7분 발표, 시각 자료, 결과물 시연, 질의응답으로 판정한다 |

### 단계별 내부 게이트

아래 게이트는 개발 피드백용이며 공식 탈락 기준이 아니다.

- **IDEA 게이트:** REG1, REG2, AI1, CRE1 중 하나라도 3점 미만이면 문제·근거·AI 필요성·기존 공백부터 재정의한다.
- **CONCEPT 게이트:** REG4, REG5, AI2, AI3 중 하나라도 3점 미만이면 개발 범위와 데이터·운영 설계를 먼저 보완한다.
- **PROTOTYPE 게이트:** AI4, AI5 중 하나라도 3점 미만이면 기능 추가보다 핵심 흐름과 검증을 먼저 완성한다.
- **FINAL 게이트:** PRE1, PRE2 중 하나라도 3점 미만이거나 보안·데이터 진실성 플래그가 미해결이면 발표자료와 시연 방식을 우선 보완한다.

## 4. 증거 규칙

### 4.1 증거 등급

평가 시작 시 증거 목록을 `E01`, `E02`처럼 만든다.

| 등급 | 의미 | 예시 |
|---|---|---|
| `A` 직접 확인 | 평가자가 실행·원본 결과를 직접 확인 | 라이브 입력과 출력, 실행 로그, 원시 테스트 결과, 질의응답에서 즉시 재현 |
| `B` 문서화된 증거 | 위치와 내용을 식별할 수 있는 제출 산출물 | 슬라이드 번호, 코드 파일, 녹화 시각, 출처가 있는 표, 설계서, 테스트 보고서 |
| `C` 주장 | 구체적 확인 수단이 없는 설명 | “연동했다”, “정확하다”, “기관이 사용할 것이다”라는 구두·문구 주장 |
| `X` 없음 | 관련 내용이나 증거가 없음 | 미제시, 질문에도 확인 불가 |

적용 규칙은 다음과 같다.

- `X`는 0점이다.
- `C`만 있는 경우 최대 1점이다.
- 2점 이상은 반드시 관련 `A` 또는 `B` 증거를 인용한다.
- 4점 이상은 강한 직접 증거 또는 구체적 비교·검증 증거가 있어야 한다.
- FINAL의 AI4·AI5에서 5점을 주려면 적어도 하나의 `A` 증거가 필요하다.
- 팀이 자료를 내지 않은 경우는 0점으로 채점한다. 평가 도구 장애나 접근 권한 문제로 자료를 열지 못한 경우는 `BLOCKED`로 표시하고 총점을 확정하지 않는다.

### 4.2 데이터 증거

지역·통계·공공데이터는 가능한 범위에서 아래를 기록한다.

- 기관명
- 데이터명
- 기준연도 또는 수집 기간
- 지역 범위와 단위
- 원문 위치 또는 URL
- `real`(실데이터), `synthetic`(가상·합성), `mixed`(혼합) 구분

`introduce.md`는 실데이터 전체를 구하기 어려울 때 가상 데이터 시연을 허용한다. 따라서 가상 데이터를 썼다는 이유만으로 감점하지 않는다. 대신 생성 규칙, 한계, 실제 데이터로 교체할 방법을 밝혀야 한다. 가상 데이터를 실데이터인 것처럼 표시하면 데이터 진실성 위반으로 처리한다.

### 4.3 평가 확신도

각 세부 항목에 점수와 별도로 확신도를 기록한다. 확신도는 점수나 동점 처리에 반영하지 않는다.

| 확신도 | 기준 |
|---|---|
| `높음` | 직접 실행 또는 명확한 문서로 판정 가능 |
| `보통` | 간접 증거가 있으나 작은 불확실성이 있음 |
| `낮음` | 자료 충돌·설명 부족으로 판정이 불안정함 |

확신도가 낮다고 점수를 낙관적으로 올리지 않는다. 미확인 사항과 확인 질문을 별도로 적는다.

## 5. 공통 점수 앵커와 산식

항목별 구체 앵커가 공통 앵커보다 우선한다.

| 점수 | 공통 판정 |
|---:|---|
| 0 | 내용·증거가 없거나, 기준과 명백히 모순되거나, 허위로 판정됨 |
| 1 | 명칭·구호·주장만 있고 구체성 또는 확인 가능한 근거가 없음 |
| 2 | 방향은 관련 있으나 핵심 가정·설계·근거가 크게 부족함 |
| 3 | 현재 단계에서 필요한 핵심 논리와 최소 증거가 확인됨 |
| 4 | 직접 근거, 비교, 검증이 충실하고 주요 위험·한계를 다룸 |
| 5 | 독립적으로 확인 가능하고 재현성·예외 처리·불확실성 관리까지 갖춘 탁월한 수준. 드물게 부여 |

구체 표에는 0·1·3·5점 앵커를 제시한다. 2점은 1점과 3점 사이, 4점은 3점과 5점 사이일 때만 부여한다.

```text
AI 소계       = AI1 + AI2 + AI3 + AI4 + AI5 + AI6       (0~30)
지역 소계     = REG1 + REG2 + REG3 + REG4 + REG5 + REG6 (0~30)
창의 소계     = CRE1 + CRE2 + CRE3 + CRE4 + CRE5 + CRE6 (0~30)
발표 소계     = PRE1 + PRE2                              (0~10)
총점          = 네 소계의 합                            (0~100)
동점 비교 벡터 = [AI 소계, 지역 소계, 창의 소계, 발표 소계]
```

평균적인 3점은 총 60점이다. 5점은 “좋아 보인다”는 인상만으로 주지 않는다.

## 6. 세부 루브릭

### 6.1 AI 기술 활용성·완성도 — 30점

| ID | 평가 기준 | 0점 | 1점 | 3점 | 5점 |
|---|---|---|---|---|---|
| **AI1** | **AI 필요성·문제 적합성** | 서비스에서 AI 역할을 찾을 수 없거나 문제와 무관함 | “AI 챗봇/추천” 같은 이름만 있고 사용자 가치와 연결되지 않음 | 입력→AI 처리→출력→사용자 행동이 문제 해결 가치로 연결됨 | 비AI 기준선과 비교해 AI가 필요한 이유를 입증하고, AI가 실패하거나 쓰이지 말아야 할 조건까지 설명함 |
| **AI2** | **기술 이해도·설계 타당성** | 기술적으로 불가능하거나 핵심 개념을 잘못 설명함 | 모델명·RAG·예측 등 용어만 나열함 | 모델·프롬프트·검색·예측·비전·최적화 등 선택과 파이프라인이 목적에 맞음 | 대안 구조를 비교하고 정확도·비용·지연·복잡도 절충, 구성요소 경계, 실패 대응까지 명확함 |
| **AI3** | **데이터·지식·그라운딩 품질** | 데이터가 없거나 실·가상 여부를 허위 표시함 | “공공데이터를 쓴다” 정도이며 출처·구조·처리가 없음 | 출처, 기간, 스키마, 최소 전처리, 실·가상 구분과 AI 연결 방식이 있음 | 대표성·품질·편향·사용 권한을 검토하고 최신성 관리, 근거 인용 또는 데이터 교체 절차까지 검증함 |

## 7. 강제 상한과 위험 플래그

먼저 세부 앵커로 원점수를 판단한 뒤 아래 상한을 적용한다. 최종점수는 `min(원점수, 상한)`이다.

| 확인된 조건 | 적용 규칙 |
|---|---|
| AI가 서비스가 아니라 아이디어 정리·발표자료 작성에만 쓰임 | AI1~AI4 각각 최대 1점 |
| FINAL에서 실행 가능한 핵심 AI 흐름이 없고 계획·정적 목업만 있음 | AI4 최대 2점 |
| FINAL에서 선별된 정적 출력만 있고 새 입력 또는 처리 과정을 확인할 수 없음 | AI4 최대 3점 |
| 평가 지표·테스트 기준 없이 성공 사례 하나만 제시 | AI5 최대 1점 |
| 지역 문제의 핵심 수치에 출처가 전혀 없음 | REG2 최대 1점 |
| 기관명은 있으나 데이터명·기간·지역 범위를 식별할 수 없음 | REG2 최대 2점 |
| 지역명만 바꾸면 그대로 쓸 수 있고 지역 데이터·제도·사용 흐름의 변화가 없음 | REG4 최대 2점 |
| 기존 대안 비교가 전혀 없음 | CRE1 최대 1점, CRE2·CRE3 각각 최대 3점 |
| 가상·합성 데이터를 고의로 실데이터처럼 표시 | AI3=0, REG2=0, `DATA_INTEGRITY` 플래그 |
| 근거 없이 기관 협약·도입·데이터 권한이 확보됐다고 표시 | REG5 최대 1점, `UNVERIFIED_PARTNERSHIP` 플래그 |
| API 키가 코드·화면·저장소·발표자료에 노출 | AI6=0, `SECRET_EXPOSURE` 플래그 및 운영진 확인 요청 |
| 동의·비식별화 없이 실명·연락처 등 개인정보를 AI 입력에 사용 | AI6=0, `PRIVACY` 플래그 및 운영진 확인 요청 |
| 확인 방법 없는 성능 수치 또는 사용자 반응을 사실처럼 제시 | 관련 AI5 또는 REG6 최대 1점, `UNVERIFIED_CLAIM` 플래그 |

플래그는 임의 실격 사유가 아니다. 실격·공정성 위반 여부는 운영진만 결정한다. 한 결함이 두 항목에 실제로 별도 영향을 주는 경우에만 둘 다 낮추고 각각 이유를 쓴다.

## 9. 에이전트 평가 절차

Claude, Codex 또는 사람 평가자는 아래 순서를 바꾸지 않는다.

1. 평가 단계와 대상 주제 코드를 선언한다.
2. 받은 자료와 받지 못한 자료를 나눈다.
3. 평가 가능한 사실을 증거 원장에 기록한다.
4. 실데이터·가상데이터·혼합데이터를 구분한다.
5. AI1부터 PRE2까지 독립적으로 원점수를 정하고 증거 ID를 연결한다.
6. 강제 상한과 위험 플래그를 적용한다.
7. 네 소계, 총점, 동점 벡터를 계산한다.
8. 사실·가정·추론·미확인을 분리한다.
9. 가장 강한 점 3개와 가장 큰 감점 원인 3개를 쓴다.
10. 다음 단계 조치 3개를 `행동 + 대상 루브릭 ID + 필요한 증거` 형식으로 제시한다.
11. 아래 검산을 통과한 뒤에만 결과를 확정한다.

### 검산 규칙

- 세부 점수 20개가 모두 0~5 정수인가?
- AI·지역·창의 소계가 각각 0~30, 발표 소계가 0~10인가?
- 총점이 네 소계의 합과 정확히 같은가?
- 동점 벡터가 `[AI, 지역, 창의, 발표]`와 정확히 같은가?
- 2점 이상인 모든 항목에 A 또는 B 증거 ID가 있는가?
- 4~5점 판정에 구체적 비교·검증·직접 근거가 있는가?
- 상한 규칙을 위반하지 않았는가?
- IDEA·CONCEPT·PROTOTYPE 결과를 `예비점수`로 표시했는가?
- `BLOCKED` 자료가 있는데 총점을 확정하지 않았는가?

## 11. 아이디어 비교용 최소 입력 양식

IDEA 단계에서 여러 후보를 비교하려면 각 아이디어가 적어도 아래 내용을 같은 분량으로 제출해야 한다. 정보량이 다른 아이디어를 그대로 비교하지 않는다.

```md
- 아이디어명:
- 배정 주제 코드:
- 문제 한 문장: [누가/어디서] [무슨 원인] 때문에 [어떤 손실]을 겪는다.
- 지역 근거 2개: [기관·데이터명·기간·핵심 수치]
- 핵심 사용자와 운영 주체:
- 기존 대안 2개와 남은 공백:
- 해결 원리 한 문장:
- AI가 필요한 이유와 비AI 대안:
- AI 흐름: [입력] → [처리] → [출력] → [사용자 행동]
- 사용할 데이터: [실/가상 구분·확보 방법]
- 3일 안에 만들 핵심 흐름 1개:
- 가장 위험한 가정과 2시간 내 검증법:
- 성공 KPI와 측정법:
- 개인정보·오탐·편향·보안 위험:
- 60초 설명 또는 1장 콘셉트 시트:
```

아이디어 비교 결과에는 총점만 제시하지 말고 반드시 아래도 함께 제시한다.

- 후보별 치명적 가정 1개
- 후보별 3일 내 구현 가능 범위
- 점수 차이를 만든 직접 증거
- 선택 아이디어의 가장 큰 반대 논거
