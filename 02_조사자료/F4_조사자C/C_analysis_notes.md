## 2. 90개 사업 담당부서 대응표 (청년정책 스코프에서 확립한 방법)

시행계획 PDF 안에 사업마다 "담당부서·전화번호"가 실제로 박혀 있어서, 조직도를 따로 볼 필요 없이 **90건 전부 부서·전화번호 추출에 성공했다**(`C0_policy_department_map.csv`). 청년정책담당관이 23건(25.6%), 나머지 74.4%가 32개 부서에 분산 — "부서 분산"이 추측이 아니라 실측이 됐다.

이 방법(사업 상세 마지막 페이지의 "담당부서" 패턴 정규식 추출)은 6대산업 B1의 원문 사업계획서(R-04, B가 정보공개청구 중)가 확보되면 그대로 재사용 가능하다.

### 미매칭 56건 처리 방식

지방재정365 웹 UI를 수동 검색하려 했으나, 이미 로컬에 있는 세출현황 스냅샷과 대조해보니 **추가로 나온 매칭이 3건뿐**(그중 2건은 이미 알던 것, 1건은 오탐)이었다 — 즉 사이트를 더 뒤져도 같은 결과가 나올 가능성이 높아 수동 검색을 중단했다. 최종적으로 38건 매칭 확정 / 2건 산하기관 소관 확정 / 50건 `NOT_PUBLICLY_VERIFIABLE`로 마감했다(`C0_policy_budget_join_final.csv`).

**교훈**: "웹사이트를 더 뒤진다"보다 "이미 받아놓은 원본 데이터를 다른 각도로 다시 대조한다"가 더 빠르고 정확했다.

## 3. 지역격차 인구 정규화 — 절대값과 정규화값의 순위가 뒤집힌 사례

청년정책 스코프에서 군구별 청년사업 예산을 인구로 나눠본 결과:

| 군구 | 청년사업 수(절대값) | 1인당 예산(정규화) |
|---|---:|---:|
| 남동구 | 15건(절대 최다) | 33,702원(중위권) |
| 강화군 | 13건 | **232,613원(1위)** |
| 연수구 | 9건 | **19,400원(최저)** |

**절대값만 봤으면 "남동구 예산이 제일 크다"로 끝났을 텐데, 인구로 나누니 정반대 결론(강화군·옹진군이 압도적으로 높음)이 나왔다.** 지역격차 후보를 정규화 없이 쓰면 안 되는 이유를 실측으로 보여준 사례.

### 부작용 — 행정구역 개편 발견

이 작업 중 KOSIS 인구통계(구 체계: 중구·동구·서구)와 예산 스냅샷(신 체계: 영종구·제물포구·서해구·검단구)이 안 맞는 걸 발견했다. 이후 B가 이게 **2026-07-01 행정구역 개편**(2군8구→2군9구) 때문임을 확인하고 정확한 대응표까지 찾아놨다(B4 §0 경고1): 중구 내륙+동구→제물포구, 중구 섬→영종구, 서구→서해구+검단구.

**신설 4개 구는 여전히 옛 인구통계가 없어서 정규화가 막힌 상태다.** R-02(B가 이미 P1로 요청 중)가 풀려야 지역격차 후보의 6대산업 재정규화가 가능하다.

## 4. 워크넷 API 신청 과정에서 확인한 것

- 채용정보·직무정보(NCS)·공통코드·직업정보 4개 API 전부 승인 완료(2026-08-13, 자동승인으로 보임)
- **API 실행은 C가 직접 못 한다** — 실행 환경이 work24.go.kr/apis.data.go.kr 도메인을 차단해놨다(`host_not_allowed`). 수집 스크립트(`collect_worknet.py`)는 준비돼 있으나 로컬에서 팀원이 직접 실행해야 한다.
- 채용정보 API(`wantedApi.do`)는 파라미터가 확인됐으나, 공통코드·NCS 데이터사전 API는 정확한 엔드포인트명을 못 찾았다 — 로그인 후 "개발가이드" 페이지 확인 필요(스크립트에 TODO로 표시해둠).
