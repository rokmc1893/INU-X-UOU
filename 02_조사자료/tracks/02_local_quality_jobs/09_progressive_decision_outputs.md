# 1장 사전검토서에서 대시보드·심사보고서로 확장하는 구조

기준일: 2026-08-13

## 1. 핵심 설계

현업 부서가 신규 사업을 제안하거나 기존 사업을 계속·개편하려 할 때 **1장 정합성 사전검토서**를 먼저 만든다. 검토된 필드는 공통 정책원장에 누적되고, 같은 데이터에서 월·분기 대시보드와 위원회·예산심사용 보고서를 생성한다.

```text
현업 부서의 1장 사전검토서
        ↓ 확인·승인된 필드만 누적
공통 정책 근거원장
        ├─ 월간 변화·결측 알림
        ├─ 분기 포트폴리오 대시보드
        └─ 연간 조정위원회·예산 심사보고서
```

## 2. 공통 정책원장의 최소 필드

| 묶음 | 필드 |
|---|---|
| 식별·책임 | 정책 고유ID, 사업명, 버전, 담당부서·담당기관, 승인상태 |
| 상위 연결 | 상위 기본계획 목표, 취업정책 유형, 기여할 공통성과 |
| 문제 | 해결할 문제, 외부 수요근거, 기준일, 반대가설 |
| 대상 | 연령·거주·학력·전공·취업상태·직무 등 자격과 제외조건 |
| 수단 | 교육·인턴·매칭·기업지원·근속지원 내용과 전달기관 |
| 시간 | 모집·교육·채용·예산·성과측정 시점 |
| 성과 | 사업 고유 KPI, 브리지 KPI, 분모, 목표값, 측정주기 |
| 일자리 질 | 사업장, 직무, 계약, 임금, 4대보험, 3·6·12개월 유지 |
| 재정·권한 | 예산·집행, 법적 근거, 결정권자, 협력 필요기관 |
| 근거 | 원문 URL·문장·페이지, 수집일, 데이터 범위·결측·신뢰도 |
| 감사 | LLM 제안, 규칙 결과, 사람 수정·승인, 이의제기, 변경이력 |

## 3. 산출물 1 — 1장 정합성 사전검토서

정책 제안 전 가장 먼저 사용하는 핵심 화면이다.

1. 어떤 취업·이탈 문제를 누구에게 해결하려는가
2. 문제를 뒷받침하는 수요·성과 근거는 무엇인가
3. 해당 수단이 원인을 바꿀 수 있는 경로는 무엇인가
4. 기존 사업과 무엇이 중복되고 어디를 이어주는가
5. 사업 고유 KPI와 상위 취업·근속 브리지 KPI는 무엇인가
6. 공개·내부 데이터로 실제 측정 가능한가
7. 계속·개편·통합·추가조사 중 제안과 그 조건은 무엇인가
8. LLM 후보, 규칙 결과, 사람 승인상태는 무엇인가

사전검토서는 정책을 자동 승인하거나 반려하지 않는다. 근거가 부족하면 낮은 점수 대신 `추가조사 필요`를 반환한다.

## 4. 산출물 2 — 월·분기 포트폴리오 대시보드

사전검토서가 누적되면 다음을 별도 입력 없이 집계한다.

- 대상·직무·교육내용·기업군 중복
- 훈련→일경험→채용→근속 단계별 사업 공백
- 모집·수료·기업채용 시점 불일치
- 사업별 브리지 KPI와 측정 가능성
- 신규 근거·채용수요 변화와 마지막 갱신일
- 계속·개편·통합·추가조사 검토 대기열
- 부서 확인·미확인·이의제기 현황

주간 변화는 경보, 월간은 자료갱신, 분기는 실제 포트폴리오 검토에 사용한다.

## 5. 산출물 3 — 위원회·예산심사용 보고서

연간 공식 절차에 맞춰 다음 내용을 재구성한다.

- 상위 청년계획 목표별 취업사업 포트폴리오
- 전년도 성과와 근거 신뢰도
- 유지·개편·통합·신설·중단 검토 사업과 판단조건
- 사업 간 역할분담과 부서·기관 협업 필요사항
- 예산 증감안과 기대성과가 아니라 검증할 성과경로
- 데이터 미확보, 법적·재정·이해관계 제약
- 담당부서 확인과 반대의견

## 6. 행정기관이 사용할 유인

- 한 번 확인한 정책 필드를 시행계획·부서협의·분기점검·위원회·예산자료에 재사용한다.
- 새 보고 시스템에 중복 입력하는 대신 기존 문서에서 초안을 추출하고 담당자는 차이만 확인한다.
- 낮은 정합성 점수를 받는 것이 아니라 회의 전에 반박 가능한 근거·결측·쟁점을 확인한다.
- 부서 간 논쟁을 추상적 주장 대신 동일한 대상·기간·KPI·원문 근거로 바꾼다.
- 사업이 개편되지 않더라도 왜 유지했는지 결정기록을 남긴다.

## 7. 검색 플랫폼과의 구분

| 정책 검색·추천 서비스 | 정책 설계·의사결정 지원 서비스 |
|---|---|
| 청년이 받을 사업을 찾음 | 담당자가 만들거나 고칠 사업을 검토함 |
| 사업명·자격·신청링크 중심 | 문제–대상–수단–KPI–성과경로 중심 |
| 개인별 추천·조회가 핵심 | 계속·개편·통합 결정과 근거가 핵심 |
| 최신 정책목록이 주요 자산 | 버전 있는 정책원장과 결정이력이 주요 자산 |
| 클릭·신청이 주요 운영지표 | 정책 변경과 후속 취업·근속 성과가 장기지표 |

이 서비스의 핵심 차별점은 정보를 한곳에 모으는 것이 아니라, 정책 제안 시점에 설계 정합성을 검토하고 그 근거를 후속 결정에 재사용하는 데 있다.
