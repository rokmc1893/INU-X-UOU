# 공개 우선 정책 정합성 평가 거버넌스

기준일: 2026-08-13

## 1. 공개 원칙

정책 정합성 평가의 입력근거, 분석규칙, 결과, 불확실성, 반론과 변경이력을 기본적으로 공개한다. 시민은 점수만 보는 것이 아니라 어떤 문서와 규칙으로 어떤 판단이 만들어졌는지 확인할 수 있어야 한다.

공개는 곧 무검토 공개를 뜻하지 않는다. 각 결과에는 생성·확인 상태와 데이터 범위를 표시하며, 정정 전후 버전을 모두 남긴다.

## 2. 공개할 정보

- 정책·사업의 공식 원문 URL, 문서버전과 수집일
- 목표·대상·수단·KPI·기간·담당부서 등 구조화 필드
- 사업유형, 직무·역량 매핑과 사용한 분류체계 버전
- 수직·수평 정합성 차원별 판정과 계산규칙
- LLM이 생성한 후보와 규칙 기반 결과의 구분
- 각 사실 판단의 원문 근거 위치
- 데이터 결측, 최종 갱신일, 관측범위와 신뢰도
- 계속·개편·통합·추가조사 권고의 조건과 반대가설
- 담당부서 확인·반론·보완자료와 시스템 응답
- 모델·규칙·데이터·사람 승인 변경이력

## 3. 그대로 공개하지 않을 정보

- 참여자의 성명, 연락처, 주민등록정보, 세부 거주지와 개인 고용이력
- 소수집단 조합으로 개인을 추론할 수 있는 세부 성과표
- 법령상 비공개 사항과 공개 시 사생활을 침해할 정보
- 공개로 기업의 정당한 이익을 현저히 해칠 우려가 있는 영업상 비밀
- 계정정보, 접근키, 보안구조와 원문 이력서 등 불필요한 민감자료

공공기관 보유정보는 공개가 원칙이지만 정보공개법상 비공개 가능 정보가 존재하며, 개인정보는 목적에 필요한 최소 범위에서 처리해야 한다. 실제 공개 전에는 기관의 정보공개·개인정보 담당 검토가 필요하다.

## 4. 공개 상태 레이블

| 상태 | 의미 | 시민이 알아야 할 점 |
|---|---|---|
| 시스템 초안 | 자동 추출·분석 뒤 담당자 미확인 | 오류 가능, 정책평가 확정 아님 |
| 담당부서 확인 | 원문 필드와 사실관계 확인 | 효과·권고까지 동의했다는 뜻은 아님 |
| 이의제기 중 | 부서·기관이 근거 또는 해석에 반론 | 양측 근거를 함께 열람 가능 |
| 검토 완료 | 정해진 검토절차와 수정 반영 | 해당 기준일의 판단이며 영구 확정 아님 |
| 갱신 필요 | 데이터 유효기간 경과 또는 정책 변경 | 현재 의사결정에 그대로 사용 금지 |

## 5. 이의제기와 정정

1. 평가 대상 부서·기관이 필드·근거·분류·해석별로 이의를 제기한다.
2. 반론과 제출근거를 원 평가 옆에 즉시 표시한다.
3. 시스템 담당자가 `수용 / 부분수용 / 기각 / 추가검토`와 이유를 기록한다.
4. 수정 시 이전 버전을 삭제하지 않고 무엇이 왜 바뀌었는지 공개한다.
5. LLM 오류와 데이터 오류를 구분해 재발방지 규칙에 반영한다.

## 6. 공개 우선의 주요 위험과 통제

| 위험 | 통제 |
|---|---|
| 초안이 확정평가처럼 확산 | 상태·기준일·신뢰도를 결과와 같은 크기로 표시 |
| 낮은 점수가 기관 낙인·예산삭감 도구가 됨 | 종합순위 대신 차원별 근거, 보완조건과 이의제기 병기 |
| 부서가 유리한 지표만 입력 | 원문·필수필드·결측도 함께 공개 |
| 공개를 피하려 자료를 제공하지 않음 | 미제공을 낮은 성과가 아닌 `평가 불가능`으로 구분 |
| 작은 코호트 재식별 | 최소 집계기준, 범주화, 억제·마스킹 적용 |
| 기업 영업정보 침해 | 제3자 의견청취와 부분공개 검토 |
| 평가모델 게임 | 규칙·가중치 버전 공개, 결과 전 가중치 고정, 이상치 감사 |

## 7. 3일 프로토타입의 공개 범위

3개 실제 사업에 대해 공개자료에서 만든 정책카드, 근거행렬, 정합성 후보, 데이터 갭과 조건부 개편안을 공개한다. 실제 기관이 확인하지 않았으므로 모든 결과에 `시스템 초안·기관 미확인`을 표시한다.

개인자료를 사용하지 않으며 공개자료에 없는 취업·근속 성과를 추정하지 않는다. 프로토타입 테스트 뒤 점수 표현, 상태 레이블, 이의제기 흐름을 수정한다.
