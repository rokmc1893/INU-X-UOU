# 정책핏 인천 — 3인 조사팀 역할분담과 MVP 선정 스프린트

기준일: 2026-08-13  
목표: 실제 정책결정 구조와 실제 추진사업을 확인하고, 일곱 문제 중 **공개자료로 성능을 검증할 수 있는 첫 MVP 항목 하나**를 선정한다.

## 0. 팀 구조

| 담당 | 한 문장 책임 | 최종 산출물 |
|---|---|---|
| 조사자 A — 정책현장·행정 워크플로우 | **누가, 언제, 어떤 문서와 회의를 거쳐 정책을 발의·조정·예산화하는지 확인** | 정책결정 달력, 담당부서·역할표, 실제 사업 2건의 추진경로 |
| 조사자 B — 산업수요·사업 포트폴리오 | **실제 산업수요와 현재 추진 중인 정책·사업 전체를 같은 구조로 지도화** | 산업수요표, 정책·사업 원장, 기존사업 고려·연결 근거표 |
| 조사자 C — 성과데이터·검증설계 | **일곱 문제를 데이터 가용성과 검증 가능성으로 평가하여 MVP 항목 선정** | 데이터 카탈로그, 후보 비교표, 정답셋, MVP 권고안 |
| 사용자 — 제품책임자·기술책임자 | **세 조사결과를 서비스 흐름과 기술구조로 변환** | 사용자 여정, 기능 우선순위, 스택, 프로토타입, 최종 범위 결정 |

역할 경계는 다음과 같이 고정한다.

```text
A: 누가·언제·어떻게 결정하는가
B: 어떤 수요와 어떤 사업이 실제로 존재하는가
C: 무엇을 어떤 데이터로 검증할 수 있는가
사용자: 이것을 어떤 서비스와 기술로 구현하는가
```

## 1. 공통 조사 규칙

1. 모든 문장은 `[사실] / [추론] / [가설] / [미확인]` 중 하나로 표시한다.
2. 공식 원문을 우선하며 `기관·문서명·URL·발행일·수집일·페이지/문단`을 기록한다.
3. 검색되지 않았다는 이유로 `사업을 고려하지 않았다`, `정책이 없다`, `성과가 없다`고 결론 내리지 않는다.
4. 기존사업 고려 여부는 다음 네 상태로만 기록한다.
   - `EXPLICIT`: 공식 문서·회의·담당자 확인에서 역할분담 또는 연계가 명시됨
   - `REFERENCED`: 관련사업을 언급했지만 조정·역할분담은 불명확
   - `INFERRED`: 같은 대상·기능이지만 조사자가 관계를 추정함
   - `NOT_PUBLICLY_VERIFIABLE`: 공개자료로는 확인할 수 없음
5. 담당자는 개인 이름보다 `부서–팀–직위/역할–소관사무–공개 연락처–확인일`을 우선 기록한다. 인사이동에 대비해 개인 이름은 보조 필드로 둔다.
6. 공개 API의 `실시간` 표시는 전송방식일 수 있으므로 실제 원자료의 월·분기·연간 주기를 별도로 적는다.
7. 자료가 없으면 0점이 아니라 `미측정·기관협약 필요·정의되지 않음`으로 처리한다.
8. 세 사람은 동일한 증거원장을 사용한다.

### 공통 증거원장 필드

```text
evidence_id
claim
claim_status           # 사실/추론/가설/미확인
publisher
document_title
canonical_url
published_at
retrieved_at
page_or_section
supporting_text
coverage_limit
evidence_grade
owner_researcher
review_status
```

## 2. 조사자 A — 정책현장·행정 워크플로우

### 임무

정책 아이디어가 실제로 어느 부서에서 시작하고, 언제 기존사업 검토·부서협의·예산심사·위원회·의회 절차를 거치는지 확인한다. 서비스가 들어갈 **정확한 의사결정 순간과 실제 사용자**를 찾는 역할이다.

### 반드시 답할 질문

1. 바이오 산업정책, 청년취업사업, 교육·RISE사업을 최초 발의할 권한이 있는 부서와 팀은 어디인가?
2. `기존사업 개편 / 다음 연도 신규사업 / 추경사업 / 중앙정부 공모 대응`은 각각 언제 제안해야 하는가?
3. 아이디어가 사업계획서와 예산요구서가 되기 전에 실제로 작성·검토되는 문서는 무엇인가?
4. 어느 단계에서 유사·중복사업, 산업수요, 성과, 법·예산·권한을 검토하는가?
5. 청년정책담당관, 반도체바이오과, 교육협력·RISE, 일자리·기업지원, 예산부서의 역할과 결재선은 어떻게 다른가?
6. 청년정책조정위원회, 산업 관련 협의체, 예산부서, 시의회는 무엇을 심의하고 실제 수정권은 어디에 있는가?
7. 실제 추진된 사업 2건은 `문제발굴→부서검토→협의→예산→공고→수행→평가`를 어떻게 통과했는가?
8. 기존 추진사업을 고려했다는 사실은 어떤 문서·회의록·검토표·담당자 확인으로 남는가?
9. 어떤 자료는 공개문서에 없고 담당 공무원의 확인이 필요한가?
10. 정책핏 결과물을 누가 언제 받으면 실제 다음 문서나 회의에 사용할 수 있는가?

### 조사 범위

- 인천시 조직도와 사무분장
- 청년정책 기본계획·시행계획과 조정위원회
- 바이오산업 종합계획·협의체와 반도체바이오과 추진자료
- 본예산·추경 편성 및 시의회 심사 일정
- RISE·교육협력, 인천TP 등 수행기관 관계
- 실제 사업 2건의 공고·보도자료·예산서·의회자료·성과자료
- 가능하면 공개 연락처를 통한 짧은 사실확인 1회

### 실제 사업 추적 후보

- 청년도약기지 생산·품질관리 트랙
- 인천대 바이오의약품 제조·품질관리 양성과정
- K-NIBRT 또는 최근 바이오 인재양성 공모사업

두 건 이상을 고르되, 하나는 기존사업 개편 사례, 하나는 신규·공모 사업 사례가 좋다.

- 다음으로 현실적인 정책 제안·개편 창구와 시기를 날짜 또는 월 단위로 설명할 수 있다.
- 서비스의 작성 사용자, 검토 사용자, 결정 사용자가 각각 특정된다.
- 실제 사업 2건의 흐름에 단계별 원문 근거가 있다.
- `공식 절차`와 `추정한 실무 관행`이 섞이지 않는다.
- 기존사업을 고려하지 않았다고 공개자료만으로 과잉 단정하지 않는다.

## 3. 조사자 B — 산업수요·사업 포트폴리오

### 임무

인천 바이오산업의 실제 수요와 현재 계획·결정·모집·운영·종료된 지원사업을 같은 기준으로 구조화한다. 신규 정책이 정말 새로운지, 기존사업을 보완·연결하면 되는지를 판단할 기초자료를 만든다.

### 반드시 답할 질문

1. 인천 바이오산업의 범위를 어떤 KSIC·기업군·공간으로 정의할 것인가?
2. 생산·공정·QA·QC·GMP 인력 외에 기업이 겪는 기술·판로·금융·시설·공급망 병목은 무엇인가?
3. 최근 수요인지, 3~5년간 지속된 수요인지, 전망·정책유행인지 어떻게 구분할 것인가?
4. 인천시·인천TP·대학·중앙부처가 현재 추진하거나 이미 결정한 관련 사업은 무엇인가?
5. 각 사업은 누구에게 무엇을 언제 얼마나 지원하며 어떤 성과를 약속하는가?
6. 동일 대상·기능·직무·시설·기업군에 역할중첩 후보가 있는가?
7. 사업 사이에 추천·인계·공동기업풀·공통 KPI·공통 ID가 있는가?
8. 새 사업 문서가 기존사업을 명시적으로 검토하거나 역할을 나눈 근거가 있는가?
9. 공개자료가 없는 것은 무엇이며 어떤 기관이 보유할 가능성이 있는가?
10. 바이오 사례 밖으로 확장할 때 공통 필드와 산업별 교체 필드는 무엇인가?

### 조사 범위

- 인천 제2차 청년정책 기본계획과 연도별 시행계획
- 인천 바이오산업·경제자유구역·RISE·일자리·기업지원 계획

- 지방재정365와 인천 예산·결산
- 고용24·EIS·NCS·대학알리미·KOSIS·팩토리온·KICOX의 수요·공급 신호
- 공식 성과발표와 위원회·시의회 검토자료

## 4. 조사자 C — 성과데이터·검증설계

### 임무

일곱 문제 중 데이터로 성능을 검증할 수 있고 실제 정책결정에도 유용한 첫 MVP 항목을 선정한다. 동시에 프로토타입의 정답셋과 성공·실패 기준을 만든다.

### 평가할 일곱 후보

1. 정책 실효성 저하
2. 정책 예산의 비효율적 사용
3. 기업 경쟁력 약화
4. 인재 유출과 일자리 미스매치
5. 산업 생태계 형성 어려움
6. 지역 간 격차 심화
7. 기업의 정책 신뢰도 저하

### 후보별 채점 기준

| 기준 | 가중치 | 5점의 의미 |
|---|---:|---|
| 공개데이터 가용성 | 15% | 공식자료로 핵심 입력 대부분 확보 |
| 정책·산업·지역·시점 연결성 | 15% | 동일 분석단위로 안정적 연결 가능 |
| 정답·반례 구축 가능성 | 20% | 사람이 원문으로 참·거짓·미확인을 판정 가능 |
| 3일 성능검증 가능성 | 20% | 결과효과가 아니라도 시스템 정확도를 재현 가능하게 검증 |
| 행정 의사결정 유용성 | 15% | 실제 유지·개편·통합·신설 결정에 사용 가능 |
| 최신성·갱신 가능성 | 5% | 다음 실행에서도 반복 수집 가능 |
| 법·계약 위험의 낮음 | 5% | 비개인·재이용 가능자료 중심 |
| 장기 성과평가 확장성 | 5% | 기관자료 결합 시 후속 효과평가 가능 |

점수는 근거 URL 없이 부여하지 않는다. `데이터가 많다`보다 **정답을 만들 수 있는가**를 우선한다.

### 반드시 답할 질문

1. 각 후보에서 3일 안에 검증하려는 것은 정책효과인가, 설계진단 정확도인가?
2. 분석단위와 분모는 무엇인가?
3. 공개자료만으로 관측 가능한 입력·중간·최종지표는 무엇인가?
4. 실제 정책효과를 보려면 어떤 내부자료·비교집단·추적기간이 필요한가?
5. 긍정사례뿐 아니라 `유사하지만 중복이 아닌 사례`, `자료부족 사례`를 만들 수 있는가?
6. 어떤 오류가 정책적으로 가장 위험한가?
7. 어떤 후보를 MVP에서 제외하고 장기 모니터로 남길 것인가?

```text
usable_for_input_or_outcome, snapshot_ready
```

3. `C3_gold_set_v0.csv`

```text
case_id, policy_id, test_type,

reviewer_1, reviewer_2, agreement_status
```

정답셋에는 최소한 다음이 포함돼야 한다.

- 명시적 대상·직무·KPI 불일치 사례
- 실제 역할중첩 사례
- 유사하지만 중복이 아닌 음성사례
- 자료가 없어 `미확인`이 정답인 사례
- 최신자료와 오래된 자료가 충돌하는 사례

   - 1순위 항목, 보조 항목, 제외 항목
   - 분석단위, 데이터셋, 규칙, 화면 산출물
   - 3일·3개월·12개월 성과 구분
   - 실패 기준과 과장 금지 문구

### 프로토타입 성능지표

- 필수 정책필드 추출 정확도
- 핵심 판단의 원문 인용 정확도
- 미스매치 정밀도·재현율
- 유사사업 오탐률
- 근거부족 시 기권·`미확인` 정확도
- 두 사람의 수작업 정답 일치도
- 동일 입력 재실행 안정성
- 수작업 대비 시간과 누락항목 변화
- 규칙·가중치·자료원 변경 민감도

### 완료 기준

- 일곱 후보 전부가 같은 기준으로 채점되고 점수마다 출처가 있다.
- MVP 1순위 한 개와 보조 시각화 한 개가 선택된다.
- 정책효과 지표와 시스템 성능지표가 섞이지 않는다.
- 긍정·음성·미확인 사례가 있는 정답셋을 만들 수 있다.
- 선택한 항목이 3일 안에 검증 불가능하면 명확하게 탈락시킨다.

## 5. 현재의 잠정 MVP 우선순위

최종 결정은 조사자 C의 근거표 이후에 내리되, 현재 공개자료 기준의 출발 가설은 다음과 같다.

| 순위 | 항목 | MVP 역할 | 이유 |
|---:|---|---|---|
| 1 | 인재·일자리 미스매치 | **주 분석 모듈** | 채용공고–NCS–교육–정책을 연결해 정답·반례를 만들기 쉽고 기존 바이오 범위와 연결됨 |
| 2 | 예산 비효율 | **보조 시각화** | 공개 예산·집행자료가 있으나 정책명–예산사업 매핑과 실제 ROI는 내부자료가 필요 |
| 3 | 정책 실효성 | 상위 해석 | 독립 지표라기보다 수요·대상·수단·KPI 정합성을 묶는 개념 |
| 4 | 지역 격차 | 후속 모듈 | 군구 자료는 많지만 바이오 청년 세부셀과 정책 노출 연결이 약함 |
| 5 | 산업 생태계 | 배경 모니터 | 기업·특허·R&D 수는 가능하나 실제 협업·공급망 연결은 비공개 |
| 6 | 기업 경쟁력 | 장기 결과 | 매출·고용·수출은 관측돼도 특정 정책의 순효과 귀속이 어려움 |
| 7 | 정책 신뢰 | 별도 조사 | 특정 정책 신뢰와 참여포기 이유는 설문·인터뷰·사용로그가 필요 |

잠정 MVP 문장:

> **인천 바이오 생산·공정·QA/QC 인력수요와 취업·교육정책 10~20건을 비교해 직무·대상·시기·KPI의 공백과 역할중첩을 찾고, 공개 예산을 보조축으로 보여주는 정책 포트폴리오 진단.**

이 MVP는 `취업률을 높였다`가 아니라 `정책설계의 미스매치를 원문 근거로 정확히 찾았다`로 성능을 검증한다.

## 6. 3일 진행표와 인수인계

### 1일차 — 사실 수집과 범위 잠금

| 시점 | A | B | C | 사용자 |
|---|---|---|---|---|
| 오전 | 행정주체·결정유형·공식일정 | 산업범위·정책목록 초안 | 일곱 후보 데이터 탐색 | 사용자 흐름·기술 제약 정의 |
| 오후 | 실제 사업 2건 경로 추적 | 정책 10~20건·수요신호 구조화 | 후보 예비점수·데이터 카탈로그 | 데이터 입력 스키마·화면 골격 |
| 종료 게이트 | 실제 의사결정 순간 후보 | 분석 가능한 실제 사업목록 | MVP 1·2순위 후보 | 범위 변경 여부 결정 |

### 2일차 — 교차검증과 MVP 확정

| 시점 | A | B | C | 사용자 |
|---|---|---|---|---|
| 오전 | B의 정책별 담당·절차 확인 | A의 사례에 정책연계 근거 보강 | A·B 자료로 정답·반례 작성 | 공통 데이터모델 확정 |
| 오후 | 미확인 실무질문 정리 | 수요–정책·예산 지도 동결 | 일곱 후보 최종 채점·권고 | **MVP 항목 최종 선택** |
| 종료 게이트 | 사용자·결정시기 확정 | 코퍼스·포트폴리오 확정 | 정답셋·성능지표 확정 | 기능 범위·스택 동결 |

### 3일차 — 프로토타입용 패키지

- A: 화면에 넣을 실제 워크플로우, 사용자·회의·시기·산출문서 전달
- B: 고정 원문, 정책카드, 수요신호, 포트폴리오 관계 전달
- C: 규칙, 정답셋, 예상결과, 실패·기권 조건 전달
- 사용자: 한 개 수직 흐름을 구현하고 같은 자료로 수작업·시스템 결과를 비교

### 최종 인수인계 게이트

MVP 구현을 시작하기 전에 네 항목이 모두 `YES`여야 한다.

1. A — 이 결과를 **누가 언제 어떤 정책결정에 쓰는지** 특정했는가?
2. B — 비교할 **실제 사업과 실제 산업수요**가 원문으로 고정됐는가?
3. C — 시스템이 맞았는지 판단할 **정답·반례·미확인 기준**이 있는가?
4. 사용자 — 이를 보여주는 **한 개 사용자 흐름과 기술 범위**가 동결됐는가?

하나라도 `NO`이면 기능을 늘리지 않고 해당 조사공백부터 해결한다.

## 7. 최종 회의에서 결정할 것

30분 회의에서 다음 여섯 가지만 결정한다.

1. 첫 사용 부서와 담당 역할
2. 실제 적용할 정책결정 시점
3. MVP가 다룰 일곱 문제 중 1순위
4. 보조로 보여줄 지표 한 개
5. 비교할 실제 사업 3건과 전체 정책목록 범위
6. 3일 성공·실패 기준

서비스 기능·화면 의견은 이 여섯 항목을 결정한 뒤 사용자가 별도로 정리한다.
